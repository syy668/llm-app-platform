# 前端对接清单 v1.0（权限对齐版）

> 对齐 PRD v1.0 的需求更新：
> 1. **移除「用户与权限管理」独立页面**（用户列表 / 新增 / 编辑 / 删除均不做页面入口）；
> 2. **权限控制能力完整落地**：登录页 + token 鉴权、全局用户下拉、后端接口角色鉴权、前端按钮/页面级权限控制；
> 3. 账号由管理员在数据库 `users` 表预先初始化，v1.0 无页面 CRUD 入口。
>
> 本清单记录：页面 ↔ 接口绑定、权限矩阵（前端 × 后端双保险）、审批动作适配、PRD 分歧。

---

## 1. 权限模型总览

角色（`users.role`，PRD 7.2）：`admin`（管理员）/ `approver`（审批员）/ `viewer`（访客，只读）。

- **安全边界在后端**：每个端点通过 `Depends(require_role(...))` 强制校验（W1 冻结代码，本轮零改动）；
- **前端只做体验收敛**：无权入口不渲染、无权按钮隐藏、误访问渲染 403 面板；
- 前端矩阵定义在 `frontend/src/auth.js` 的 `PERMISSIONS`，**调整时必须与后端 require_role 同步并更新本清单**。

### 1.1 权限矩阵（已实测，2026-10-21 三角色真实请求验证）

| 能力 | 接口 | admin | approver | viewer | 后端依据 |
|---|---|:-:|:-:|:-:|---|
| 登录 | `POST /auth/login` | ✅ | ✅ | ✅ | 公开 |
| 当前用户 | `GET /auth/me` | ✅ | ✅ | ✅ | `get_current_user` |
| 退出登录 | `POST /auth/logout` | ✅ | ✅ | ✅ | 登录即可（jti 拉黑） |
| **新建任务**（提交页） | `POST /tasks`、`POST /tasks/stream` | ✅ | ❌ 403 | ❌ 403 | `require_role(ADMIN)` |
| 查看任务详情 | `GET /tasks/{id}` | ✅¹ | ✅ | ⚠️² | 三角色 + `assert_visible` |
| 查看轨迹 / 快照 / SSE | `GET /tasks/{id}/trace|snapshot|stream` | ✅¹ | ✅ | ⚠️² | 同上 |
| **审批决策**（同意/驳回） | `POST /tasks/{id}/resume` | ✅ | ✅ | ❌ 403 | `require_role(ADMIN, APPROVER)` |
| **终止任务** | `POST /tasks/{id}/cancel` | ✅ | ✅ | ❌ 403 | `require_role(ADMIN, APPROVER)` |
| 审批收件箱 | `GET /approvals`、`/approvals/{id}` | ✅ | ✅ | ❌ 403 | `require_role(ADMIN, APPROVER)` |
| 记忆库读 | `GET /memory/*` | ✅ | ✅ | ✅ | `READ_ROLES` 三角色 |
| 记忆库写 | `POST/DELETE /memory/*` | ✅ | ❌ | ❌ | `require_role(ADMIN)` |

> ¹ admin 只能看到自己创建的任务（`assert_visible`：`creator_id` 隔离）。
> ² viewer 仅能看到 **COMPLETED** 任务，其余返回 403（前端详情页已做友好提示）。
> 实测记录：approver 建任务 403/FORBIDDEN；viewer 收件箱 403；viewer 审批/终止 403；admin/approver 审批返回 409/TASK_NOT_PAUSED（业务态，说明已过权限层）；viewer 查看已完成任务 200/OK。

### 1.2 前端权限落点（本轮改动）

| 层级 | 文件 | 机制 |
|---|---|---|
| 矩阵定义 | `frontend/src/auth.js` | `ROLE_META` + `PERMISSIONS` + `can(user, perm)` + `ROUTE_GUARDS` |
| 登录态 | `frontend/src/store.js` | `store.user`（localStorage 持久化）+ `setUser` / `clearSession` |
| 全局拦截 | `frontend/src/main.js` | 未登录整屏登录页；hash 路由守卫 → 403 面板；导航按 `can()` 过滤；401 事件统一登出 |
| 用户下拉 | `frontend/src/main.js` | 右上角头像 + 账号 + 角色徽标 → 面板（角色说明 / 用户 ID / API 地址 / 退出登录） |
| 按钮显隐 | `submit.js` / `detail.js` | 终止 `can('task:cancel')`、审批 `can('approval:decide')`、新建 `can('task:create')` |
| 401 处理 | `frontend/src/api.js` | HTTP 401 → 派发 `agentflow:unauthorized` → 清会话回登录页；403 留给页面提示 |
| 登录页 | `frontend/src/pages/login.js` | 账密表单 + 三演示账号一键登录，登录后 `GET /auth/me` 取角色并按角色落位 |

**登录后默认落点**：admin → `#/submit`；approver → `#/inbox`；viewer → `#/center`（任务中心占位）。

| 页面（hash） | 绑定接口 | 权限 |
|---|---|---|

## 3. 审批动作适配（PRD 分歧记录）

| 项 | PRD v1.0 设想 | 实际实现（已绑定） | 适配结论 |
|---|---|---|---|
| 审批决策接口 | `POST /approvals/{id}/decision`（独立审批资源） | **`POST /tasks/{id}/resume`**，body：`{ decision: "APPROVED" \| "REJECTED", comment, sync: false, approval_id? }` | 前端按实际接口对接；审批单号仅作展示（`GET /approvals`），决策走任务恢复端点 |
| 驳回语义 | 驳回 → 任务失败/结束 | 驳回 → `replan` 重规划（`replan_count +1`）重跑前序；若目标本身含高危动作，重跑到该步被工具层前置校验拦截（`APPROVAL_MISSING`）→ FAILED | 前端提示语按实际语义写（"驳回并重规划"）；该行为是安全演示点，非 Bug |
| 409 处理 | 未定义 | `TASK_NOT_PAUSED`：任务已不在待审批态（可能已被他人审批） | 弹窗提交后提示"请刷新收件箱"，收件箱 15s 轮询自动收敛 |
| 审批过期 | 24h 过期 | 审批单含 `expires_at`（弹窗展示）；过期任务由超时策略处理 | 仅展示，无独立接口 |

## 4. 其他分歧与边界

| # | 分歧 / 边界 | 处理 |
|---|---|---|
| 1 | PRD 导航含「任务列表」，后端只有 `GET /tasks/{id}` | 「任务中心」做骨架占位，待接口后替换 |
| 2 | 旧控制台顶栏「连接设置」支持手动粘贴 token | 已收敛：登录页统一签发 token（手动贴 token 无角色信息，无法驱动权限 UI）；API 地址修改保留在用户下拉面板 |
| 3 | access_token 有效期 2h，refresh_token 一次性轮换 | v1.0 前端**未做自动刷新**（并发刷新竞态留待 v1.1）；过期触发 401 → 统一回登录页 |
| 4 | SSE 无法带请求头 | 维持 `?access_token=` 查询参数方案（后端 `sse_current_user` 已支持） |
| 5 | Vue 3 走 CDN（unpkg） | 断网白屏已有降级提示；内网可下载到 `frontend/vendor/` 后改 index.html 引用 |
| 6 | 前端矩阵与后端不一致时 | 以后端 403 为准；前端仅做收敛，不允许放宽（`auth.js` 头注释已声明） |
