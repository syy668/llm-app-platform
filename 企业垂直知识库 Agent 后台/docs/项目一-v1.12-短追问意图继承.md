# 项目一 v1.12：短追问意图继承（Contextual Intent Inheritance）

> 封版前的最后一项核心任务。解决「多轮 RAG 对话里，短追问被误判为 direct」的致命伤。

## 一、问题

```
用户：研发部住宿标准        -> route=rag      ✅ 正常检索
用户：去成都呢？            -> route=direct   ❌ 完全没检索
```

`direct` 路由不调用任何工具，模型只能靠历史消息「背」上一轮的答案。一旦上文没提过这个问题
（比如首轮就问「去成都呢？」），就只能答"没有资料"。

根因：**路由器只看单轮问题，看不到对话上下文**。`classify_route(llm, question)` 的入参里
根本没有"上一轮发生了什么"这个信息。

## 二、设计：规则短路，而不是让 LLM 带上文再判一次

| 方案 | 问题 |
|---|---|
| LLM 入参加上对话历史 | 每轮多一次调用；同样的历史可能给出不同路由，评测不可复现 |
| 规则短路（本方案） | 确定性、零额外调用、命中原因可解释 |

### 判定规则（`app/agent/intent_inherit.py::decide_inherit`）

同时满足三条才继承：

1. **上一轮 route ∈ {rag, db_query}**（`INHERITABLE_ROUTES`）
2. **本轮问题去空白标点后 ≤ 12 字**（`MAX_SHORT_LEN`）
3. **出现指代/延续信号**（`CONTEXTUAL_MARKERS`：呢/那/这个/那个/还有/刚才/换成/详细…）
   **或** 极短指向型疑问（≤ 8 字且含「谁/哪/几/多少/多久/是否/有没有…」）

### 刻意不继承的情形

| 情形 | 原因 |
|---|---|
| `report` / `parallel_compare` | 这两路会产出大量结构化内容，短追问几乎不可能是"再生成一份报表"，继承只会制造垃圾产出 |
| 含寒暄且无疑问词（"你好呀，今天天气不错"） | 这是闲聊，不该被拽回检索 |
| 首轮（`last_route` 为 None） | 没有可继承的意图 |
| 问题 > 12 字 | 说明是完整新问题，交给 LLM |
| 目标路由被对话参数禁用（`route_enabled[rag]=False`） | 否则继承完又被 `route_condition` 打回 direct，`route_inherited` 与实际执行路径不符，日志会误导 |

### 关于「继承成 rag」还是「继承原路由」

需求写的是"强制置为 rag"，实现上选择**继承上一轮的实际路由**（rag→rag，db_query→db_query）。
理由：上一轮查的是业务库，追问同一主题时也应该查业务库，一律变成 rag 反而会去文档里找不存在的数据。

## 四、可观测性

三层都能看到 `inherited_from_last_turn=true`：

1. **日志**（命中继承时不打印「路由决策」，而是专门的继承日志）：
   ```
   路由继承: rag -> rag (inherited_from_last_turn=true, reason=contextual_marker(len=5))
   ```
   未命中时也会打 reason，便于解释"为什么这次没继承"：
   ```
   路由决策: direct (inherited_from_last_turn=false, reason=greeting_without_query)
   ```
2. **接口响应**：`{"route_inherited": true}`
3. **前端**：路由标签后多一个「继承」小徽标

## 七、遗留与边界

1. **继承只覆盖「追问」**：如果用户换个说法问新主题（"那销售部的呢"—— 含"那/呢"，会继承；
   "销售部标准呢"—— 同样继承），但完全换话题却恰好很短（"今天几号"含"几"，会继承 rag），
   会多一次无意义检索。这属于规则的固有代价，比"该检索却没检索"轻得多。
2. **`route_inherited` 只存在于实时响应**，历史消息没落库，重开会话后徽标不会回显
   （路由本身仍存在 `messages.agent_route`）。
3. **Redis 环境**：本机 Docker Desktop 当前未运行，后端以 `FAKE_REDIS=true` 临时启动
   （`/api/v1/health` 显示 `redis_backend=fake`、`rate_limit=disabled`）。
   恢复杂志生产口径需要手动启动 Docker Desktop 并启动 redis-stack 容器，然后不带
   `FAKE_REDIS` 覆盖重启后端。
