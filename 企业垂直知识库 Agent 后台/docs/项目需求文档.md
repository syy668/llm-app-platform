# EvalAgent 项目需求文档

> 项目全称：企业垂直知识库 Agent 后台 + EvalAgent RAG 自动化评测平台（前后端分离）
> 技术栈：FastAPI + SQLAlchemy + MySQL 8 + Redis 7 + ChromaDB + LangGraph + RAGAS ｜ Vue3 + TypeScript + Element Plus + ECharts + Vite
> 版本：v1.5（工程化收尾轮） ｜ 更新日期：2026-10-20

---

## 1. 项目定位与目标

面向 B 端的企业垂直知识库智能问答平台，并在此基础上扩展 **RAG 自动化评测与 A/B 调优能力**：

1. **知识库问答（Agent）**：文档上传 → 解析 → 分块 → 向量化 → 混合检索 → LLM 生成回答，支持 LangGraph 三路工具编排（RAG 检索 / 业务库查询 / 报表生成）；
2. **RAGAS 自动化评测**：构建评测数据集 → 批量跑评（并发 + 重试 + 超时治理）→ 四项指标（faithfulness / answer_relevancy / context_precision / context_recall）→ BadCase 定位、分层指标、A/B 对比；
3. **平台工程化**：RBAC 双重权限校验、双 Token 会话安全、Trace 全链路日志、统一响应体、Docker 一键部署。

## 2. 功能模块总览

| 模块 | 核心能力 |
|---|---|
| 认证与用户管理 | 登录/登出/刷新令牌/修改密码；bcrypt 哈希；Redis session（HMAC 签名 token）；管理员用户 CRUD + 软删除 + 审计日志 |
| 知识库管理 | CRUD + 分页搜索 + 统计；三级访问控制（管理员/创建者/授权用户） |
| 文档管理 | 多格式上传（PDF/docx/xlsx/txt/md）→ 解析→分块→向量化全链路；SHA256 去重（409）；删除级联清理 MySQL + Chroma + BM25 |
| RAG 检索问答 | 向量 + BM25 混合检索、RRF 融合排序；Embedding/LLM 提供方可切换（hash/openai/mock/anthropic）；返回 answer + sources 引用溯源 |
| 会话 | 多轮对话持久化、会话重命名、请求级参数覆盖（检索库/top_k/工具开关） |
| Agent 编排 | LangGraph 三路条件路由 + 并行对比节点 + 工具重试 + 消息落库 |
| RAGAS 评测 | 数据集管理（支持 stratum 分层标注）、异步评测任务（pending→running→done/failed）、请求级 rag_config 实验参数 |
| 评测分析 | BadCase 分页（后端筛选）、stratum 分层指标聚合、A/B 两两对比（后端对齐计算） |
| 报表与 Trace | 评测报表导出；Trace 全链路日志（节点耗时/token 用量/工具调用明细） |
| 系统监控 | 健康检查（DB+Redis）；系统配置在线热更新（LLM 模型/密钥掩码/限流/超时，`data/system_config.json` 持久化） |
| 前端（Vue3） | 登录、知识库、对话、评测（数据集/运行/对比/分层/BadCase）、用户管理、系统配置；Axios 双 Token 无感刷新 |

## 3. P0~P3 迭代清单

### P0 —— 评测基础闭环与稳定性修复

- 评测数据集创建 / 样本批量导入 / 运行触发（异步后台任务）/ 运行详情 / 得分明细分页；
- 并发评测（`EVAL_MAX_CONCURRENCY`，默认 2，防打满 LLM 配额 429）；
- 单样本失败自动重试（`EVAL_RETRY_ATTEMPTS`）+ 得分批量落库（`EVAL_SCORE_BATCH_SIZE`）；
- RAGAS 超时治理（根因修复，见《项目难点与踩坑总结》第 1 条）；
- 评测接口权限收口：GET 登录可读、POST/DELETE 仅管理员。

### P1 —— 评测增强（B1 系列）

- **B1-4 BadCase 后端分页筛选**：`metric` 白名单 + `threshold` 阈值，筛选在 SQL 层完成，前端只渲染；
- **B1-5 A/B 两两对比**：`POST /eval/runs/compare`，后端完成样本 question 对齐、四项指标 Δ 差值与汇总计算，`|Δ|>0.1` 判定差异样本（阈值随响应返回）；跨数据集对比返回 400；
- **分层难例（stratum）**：样本导入支持 `stratum` 分层标注（≤64 字符），落库至 eval_dataset_items；
- 系统配置多服务商热更新：模型名/接口地址/API Key（写-only，读取返回掩码）/温度/限流/超时。

### P2 —— 稳定性与可观测（B2 系列）

- **B2-1 僵死评测任务自愈**：应用启动时一次性扫描 running 超过 `EVAL_STALE_RUN_SECONDS`（默认 600s）的任务置为 failed；
- **B2-4 分层指标聚合**：`GET /eval/runs/{id}/stratum_metrics`，按 stratum 分组 SQL AVG 聚合四项指标，stratum=null 统一表示"未分层"；
- 请求级 `rag_config`（chunk_size / search_mode / top_k）随评测任务持久化并透传问答链路，支持向量/混合检索模式实验；
- SSE 流式问答、Trace 汇总统计、AI 限流、token 用量统计。

### P3 —— 会话安全（双 Token 改造）

- access_token 缩短为 30 分钟 + refresh_token 7 天一次性轮换；
- `POST /auth/refresh-token` 新端点（旧 `/auth/refresh` 保留兼容）；
- 登出时 refresh_token 进 Redis 黑名单（TTL 与有效期一致），实现主动踢下线；
- 前端 Axios 401 无感刷新（锁 + 请求队列，见《项目难点与踩坑总结》第 5 条）；
- RBAC 前后端双重权限校验（见《项目难点与踩坑总结》第 6 条）。

## 4. 业务规则（全局统一口径）

### 4.1 空值口径

| 场景 | 规则 |
|---|---|
| 指标均值 | SQL `AVG` 忽略 NULL；样本超时/失败导致指标缺失时**不拉低均值、不计 0 分** |
| BadCase 筛选 | 仅 `metric 非空 且 metric < threshold` 判为 BadCase；NULL 指标不参与 |
| A/B 对齐 | 单侧缺失样本：另一侧记 null，Δ 记 null，不参与汇总均值；`is_diff` 仅对双侧有值样本判定 |
| 分层聚合 | stratum 为 null 统一表示"未分层"（含历史数据与样本已删除），单列展示不丢弃 |
| 汇总兜底 | run.metrics 未落库时，A/B 汇总由得分现算（仅非空值均值），口径与评测落库一致 |

### 4.2 超时与重试策略

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `EVAL_RAGAS_TIMEOUT` | 600s | RAGAS evaluate() 整体超时（库默认 180s 过短，长样本判分超时会导致指标静默变 None 丢失） |
| `EVAL_LLM_TIMEOUT` | 120s | RAGAS Judge LLM 单请求超时 |
| `EVAL_LLM_MAX_RETRIES` | 3 | Judge LLM 单请求最大重试（0~10） |
| `EVAL_RETRY_ATTEMPTS` | 2 | 单样本失败自动重试次数（含首次，1~5） |
| `EVAL_STALE_RUN_SECONDS` | 600s | 启动时僵死任务判定阈值 |
| `SESSION_TTL_SECONDS` | 1800 | access_token 有效期（Redis 滑动过期） |
| `REFRESH_TTL_SECONDS` | 604800 | refresh_token 有效期（7 天） |

### 4.3 权限规则（RBAC 双重校验）

| 资源 | 读（GET） | 写（POST/PUT/DELETE） |
|---|---|---|
| 评测数据集/运行 | 登录用户 | 仅管理员 |
| 系统配置读取 | 登录用户 | 仅管理员 |
| 用户管理 | 仅管理员 | 仅管理员 |
| Trace 日志 | 仅管理员 | - |
| 知识库 | 管理员 / 创建者 / 被 kb_permissions 授权用户 | 同左（管理操作需 write 授权） |
| 会话 | 仅本人（管理员也不例外） | 仅本人 |
| 限流 | AI 问答接口按用户级阈值限流（阈值可配置热更新） | - |

- **后端**：`get_current_user`（登录校验）→ `get_current_admin`（角色校验）→ 资源归属校验（owner/授权）三级依赖注入；
- **前端**：路由守卫按角色控制页面可见性，但**仅作体验优化**，一切以服务端校验为准（防止绕过前端直调 API）；
- 管理员敏感操作写入 `operation_logs` 审计（操作人/动作/对象/IP）。

## 5. 非功能需求

1. **统一响应体**：`{code, message, data}` 三键结构，失败 data 恒为 null；
2. **Trace 链路**：全局 TraceID 中间件（复用 `X-Request-ID` 或自动生成），响应头 `X-Trace-ID` 回写，全部日志自动携带；
3. **异常分级**：`APP_ENV=dev` 返回完整堆栈便于排障；`prod`（默认）只返回简洁提示，堆栈仅写服务端 error 日志（含 trace_id/路径/用户ID）；
4. **测试**：后端 pytest 150+ 用例全量通过（离线运行，不依赖 MySQL/Redis/LLM）；前端 vue-tsc 零类型错误；
5. **部署**：Docker 单机一键部署（4 服务编排），无需宿主机 Python/Node 环境。

## 6. 约束

- 不新增任何 pip/npm 第三方依赖；
- 全部增量修改，不改动已稳定的业务代码；
- 数据库表结构只增不改（`AUTO_CREATE_TABLES` 幂等建表，兼容旧库升级）。
