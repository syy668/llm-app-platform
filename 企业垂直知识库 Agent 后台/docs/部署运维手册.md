# EvalAgent 部署运维手册

> 覆盖：本地开发环境搭建 / Docker 一键部署 / 环境变量说明 / 数据库初始化 / 日志查看
> 适用系统：Windows 10/11（Docker Desktop）、Linux（Docker Engine）

---

## 1. 本地开发环境搭建（不用 Docker）

### 1.1 后端

```bash
# 1) Python 3.11+ 建议使用独立虚拟环境
cd 企业垂直知识库\ Agent\ 后台
python -m venv .venv
source .venv/Scripts/activate        # Windows Git Bash；cmd 用 .venv\Scripts\activate.bat

# 2) 安装依赖
pip install -r requirements.txt
pip install -r requirements-dev.txt  # pytest 等开发依赖

# 3) 配置环境变量
cp .env.example .env                 # 按需修改 DATABASE_URL / REDIS_URL / SECRET_KEY / LLM_*

# 4) 初始化数据库与账号
mysql -uroot -p < scripts/init_db.sql
python scripts/seed.py --username admin --password <密码> --role admin

# 5) 启动
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
# 接口文档：http://localhost:8000/docs
```

> 无 MySQL/Redis 时可离线运行：`.env` 设 `LLM_PROVIDER=mock`、`FAKE_REDIS=true`，DATABASE_URL 可临时用 sqlite（完整测试套件即以此方式离线执行）。

### 1.2 前端

```bash
cd ../EvalAgent/evalagent_vue
npm install
npm run dev        # 开发服务器 http://localhost:5174
npm run build      # 生产构建（含 vue-tsc 类型检查）-> dist/
npm run typecheck  # 仅类型检查
```

前端通过 `.env` 的 `VITE_UPSTREAM_API_BASE_URL` 指向后端（默认 `http://127.0.0.1:8000/api/v1`）。

### 1.3 运行测试

```bash
# 后端全量测试（离线，不依赖任何外部服务）
./.venv/Scripts/python.exe -m pytest -q        # 150+ 用例
```

sqlite 测试兼容方案已固化在 `tests/conftest.py`（BigInteger→INTEGER 方言补丁 + 文件型 sqlite + StaticPool），新增测试直接复用 `sqlite_engine` / `eval_db` 夹具即可。

## 2. Docker 一键部署（推荐，单机仅需 Docker）

### 2.1 前置条件

- Windows：安装 [Docker Desktop](https://www.docker.com/products/docker-desktop/) 并启动；
- Linux：安装 Docker Engine 24+（含 docker compose 插件）；
- 宿主机 **无需** 配置 Python / Node / MySQL / Redis。

### 2.2 目录结构要求

```
AI_Project_Workspace/
├── 企业垂直知识库 Agent 后台/     # 后端 + docker-compose.yml + deploy/
│   ├── Dockerfile                 # 后端多阶段镜像（builder venv → runtime）
│   ├── docker-compose.yml         # 4 服务编排
│   ├── .dockerignore
│   ├── .env.example
│   └── deploy/{start,stop}.{sh,bat}
└── EvalAgent/evalagent_vue/       # 前端（compose 以 ../EvalAgent/evalagent_vue 为构建上下文）
    ├── Dockerfile                 # 前端多阶段镜像（node build → nginx）
    ├── nginx.conf                 # history 回退 + /api 反代 + gzip
    └── .dockerignore
```

### 2.3 一键启动

```bash
# Windows：双击或命令行执行
deploy\start.bat
# Linux / Git Bash
bash deploy/start.sh
```

脚本自动完成：检查 Docker → 生成 .env（如缺失）→ `docker compose up -d --build` 拉起 4 个服务：

| 服务 | 镜像 | 说明 |
|---|---|---|
| mysql | mysql:8.0 | 数据持久化（volume `mysql_data`）+ 健康检查；首启自动执行 `scripts/init_db.sql` |
| redis | redis:7-alpine | AOF 持久化（volume `redis_data`）+ 健康检查 |
| app | evalagent-backend | FastAPI 后端，等 mysql/redis 健康后自动启动，uvicorn 启动，自动建表 |
| frontend | evalagent-frontend | nginx 托管 Vue3 dist；history 路由回退；反代 `/api` 到 app:8000；gzip |

启动完成后的访问入口：

- **前端**：http://localhost
- **后端 Swagger 文档**：http://localhost:8000/docs
- **健康检查**：http://localhost:8000/api/v1/health ｜ nginx 探活：http://localhost/nginx-health

### 2.4 初始化管理员（首次部署必做）

```bash
docker compose exec app python scripts/seed.py --username admin --password <密码> --role admin
```

### 2.5 一键停止 / 清理

```bash
deploy\stop.bat              # 停止（保留数据卷与镜像）
deploy\stop.bat clean        # 停止 + 删除数据卷（MySQL/Redis 数据不可恢复！）
deploy\stop.bat purge        # 停止 + 删数据卷 + 删本地构建镜像（彻底清理）
# Linux 对应 bash deploy/stop.sh [clean|purge]
```

## 3. 环境变量说明（.env，参考 .env.example）

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `DATABASE_URL` | ✅ | - | 如 `mysql+pymysql://root:密码@mysql:3306/kb_agent?charset=utf8mb4`（compose 内主机名为 `mysql`） |
| `REDIS_URL` | ✅ | - | 如 `redis://redis:6379/1`（compose 内主机名为 `redis`）。**末尾库号按项目独占**：本项目建议 `/1`，不要与其它服务共用 `/0`，否则任一方 `FLUSHDB` 或键名撞车会互相影响 |
| `SECRET_KEY` | ✅ | - | token 签名密钥，`python -c "import secrets;print(secrets.token_urlsafe(48))"` 生成 |
| `FAKE_REDIS` | - | false | true 时用内存 Redis（仅本地/CI 离线）：会话不跨进程、重启即失效，且 **AI 问答限流停用**，`/health` 会显示 `redis_backend=fake / rate_limit=disabled` |
| `AI_RATE_LIMIT_PER_MINUTE` | - | 30 | 每用户每分钟 AI 问答上限，作用于 `/conversations/*/chat`、`/chat/stream`、`/kbs/{id}/query`；也可在系统配置页热更新 |
| `APP_ENV` | - | prod | dev=异常返回完整堆栈；prod=只返回简洁提示（生产务必 prod） |
| `SCHEMA_CHECK_MODE` | - | strict | 启动期 Schema 自检：`strict`=ORM 缺列/缺表时中止启动并打印可执行的 `ALTER TABLE`；`warn`=只告警继续启动；`off`=关闭。数据库连不上不算漂移，只警告跳过 |
| `LOG_LEVEL` | - | INFO | 日志级别 |
| `CORS_ORIGINS` | - | * | 跨域来源，逗号分隔 |
| `SESSION_TTL_SECONDS` | - | 1800 | access_token 有效期（30 分钟） |
| `REFRESH_TTL_SECONDS` | - | 604800 | refresh_token 有效期（7 天） |
| `EMBEDDING_PROVIDER` | - | hash | hash=本地特征哈希（免密钥）/ openai=OpenAI 兼容 |
| `EMBEDDING_API_BASE/_KEY/_MODEL/_DIM` | - | - | openai 时的接口地址/密钥/模型/维度 |
| `LLM_PROVIDER` | - | mock | mock=回显检索结果 / openai / anthropic |
| `LLM_API_BASE/_KEY/_MODEL` | - | - | LLM 接口地址/密钥/模型 |
| `LLM_MAX_TOKENS` | - | 2048 | 单次回答输出上限（64~32768）。既是成本封顶，也是截断点：命中后回答末尾会自动追加「已达到最大长度限制」提示，并在 `trace_logs.is_truncated` 标记，可据此统计截断率反推该值 |
| `CHAT_HISTORY_MAX_TURNS` | - | 5 | 送入 LLM 上下文的历史轮数（1~50，1 轮 = 1 问 + 1 答）。超出丢弃最早的轮次 |
| `CHAT_HISTORY_MAX_CHARS` | - | 2000 | 历史字符总预算（200~50000）：即使轮数没超，超预算也从最早的消息开始丢。与上一项同时生效，两个维度各自封顶 |
| `EVAL_CONCURRENT_ENABLE` | - | true | 并发评测开关 |
| `EVAL_MAX_CONCURRENCY` | - | 2 | 并发上限（1~10） |
| `EVAL_RETRY_ATTEMPTS` | - | 2 | 单样本重试次数（1~5） |
| `EVAL_SCORE_BATCH_SIZE` | - | 10 | 得分批量落库阈值 |
| `EVAL_RAGAS_TIMEOUT` | - | 600 | RAGAS 整体超时（秒） |
| `EVAL_LLM_TIMEOUT` | - | 120 | Judge LLM 单请求超时（秒） |
| `EVAL_LLM_MAX_RETRIES` | - | 3 | Judge LLM 单请求重试 |
| `EVAL_STALE_RUN_SECONDS` | - | 600 | 僵死评测任务判定阈值 |
| `MAX_FILE_SIZE_MB` | - | 20 | 上传单文件大小上限 |
| `CHROMA_PERSIST_DIR` / `UPLOAD_DIR` | - | chroma_db / uploads | 向量库与上传目录（compose 挂载卷落盘） |
| `SYSTEM_CONFIG_FILE` | - | data/system_config.json | 系统配置热更新持久化文件 |

> compose 覆盖规则：容器内 `DATABASE_URL` / `REDIS_URL` / `APP_ENV` 由 docker-compose.yml environment 强制指定（服务名解析），其余项沿用 .env。

## 4. 数据库初始化

1. **自动建库**：mysql 容器首次启动时按 `MYSQL_DATABASE=kb_agent` 建库，并执行挂载的 `scripts/init_db.sql` 建表；
2. **自动建表**：后端启动时 `AUTO_CREATE_TABLES=true` 走 SQLAlchemy `create_all`（幂等，只建缺失表，v1.5 新增表自动补齐，旧表结构永不改动）；
3. **初始化账号**：`docker compose exec app python scripts/seed.py --username admin --password <密码> --role admin`；
4. **备份/恢复**：
   ```bash
   docker compose exec mysql mysqldump -uroot -p<密码> kb_agent > backup.sql     # 备份
   docker compose exec -T mysql mysql -uroot -p<密码> kb_agent < backup.sql      # 恢复
   ```
5. **数据落盘位置**：MySQL/Redis 数据在 named volume（`mysql_data` / `redis_data`）；Chroma 向量库、上传文件、系统配置在宿主机 `./chroma_db`、`./uploads`、`./data`（随项目目录保留）。

## 5. 日志查看与排障

### 5.1 日志格式

所有服务日志直出 stdout，统一格式：

```
2026-10-20 20:53:32 | ERROR | trace_id=2df5fc56... | app.core.exception_handler | 请求异常 | POST /api/v1/auth/refresh-token | status=401 | user_id=匿名 | UnauthorizedError: 刷新令牌无效或已过期
```

- `trace_id`：全局唯一追踪 ID，来自 `X-Trace-ID` 响应头（或前端传入的 `X-Request-ID`），**一条请求的全部日志共享同一 trace_id**， grep 一次即可还原完整调用链；
- 未处理异常自动打 error 日志（含 trace_id / 请求路径 / 用户ID）；生产环境响应体不含堆栈，仅日志中有完整堆栈。

### 5.2 常用命令

```bash
docker compose ps                        # 服务状态与健康检查结果
docker compose logs -f app               # 跟随后端日志
docker compose logs -f frontend          # 跟随 nginx 日志
docker compose logs app | grep <trace_id>   # 按 TraceID 检索一次请求的全链路日志
docker compose restart app               # 重启后端
docker compose exec app python -c "..."  # 容器内执行脚本
```

### 5.3 常见问题

| 现象 | 排查 |
|---|---|
| 前端 502 / API 不可达 | `docker compose ps` 看 app 是否 healthy；`docker compose logs app` 看启动报错 |
| mysql 健康检查失败 | 首次启动初始化较慢，等 healthcheck 通过后 app 才会启动（start_period 30s） |
| 8000 / 80 端口被占用 | 修改 docker-compose.yml 中 ports 左侧宿主端口 |
| 评测任务一直 running | 重启 app 触发僵死任务自愈（超 600s 置 failed）；检查 LLM_API_BASE 可达性 |
| 登录 401 且刷新也失败 | Redis 黑名单/过期所致，重新登录即可；确认 redis 容器健康（AOF 卷未损坏） |
| 启动失败并报「数据库结构落后于 ORM 模型」 | ORM 新增了列但存量库未升级（`create_all` 不会给已有表补列）。按日志里给出的 `ALTER TABLE ... ADD COLUMN` 逐条执行后重启；纯演示环境可临时 `SCHEMA_CHECK_MODE=warn` 只告警不阻断 |
