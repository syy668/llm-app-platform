## 1. 开场（30 秒，先建立认知）

打开 http://127.0.0.1:5173，先不操作，讲这一段：

> 这是一个多智能体任务编排平台。用户只提一个业务目标，系统自己拆成 DAG、调工具取数、自我评审，遇到高危动作会停下来等人批。
> 全链路七个节点：**Planner → human_gate → Executor → Reviewer → Summarizer → Notifier**，外加 Replan 兜底。

界面顶部右侧有两个关键元素：**「连接设置」按钮** 和 Token 状态徽标。

## 3. 场景 A：纯分析任务（不触发审批）· 约 40 秒

**目的**：先证明「能自己干活」，建立基线。

| 步骤 | 操作 | 预期 |
|---|---|---|
| 3.1 | 回到「新建任务」页，点 **「纯分析（不触发审批）」** | 目标框自动填入：`分析上周 GMV 与转化率变化，归因到品类` |
| 3.2 | 确认时间窗（默认即可），点 **「提交并开始」** | 右侧「实时进度」出现 `SSE open` 徽标，事件数开始跳动 |
| 3.3 | 盯右侧事件控制台 3~5 秒 | 依次滚动：`state_update planner` → `executor` → `tool_call sql-query` → `reviewer` → `summarizer` → `complete` |
| 3.4 | 状态徽标变绿 **已完成**，点 **「打开详情 / 回放」** | 跳到任务详情页 |

**详情页要指的四块**（从上到下）：

1. **顶部信息区**：任务号 `AF...`、trace_id、Token 消耗（本场景约 **3.2k**）、创建/结束时间
2. **DAG 画布**：节点按执行顺序高亮，能看出谁依赖谁
3. **子任务表**：3 行（取数 / 归因 / 汇总），每行有 `tool_hint` 与 `result_summary`
4. **评审与报告**：综合分 **4.6 / 5**（阈值 3.5，判「通过」）、下方 markdown 报告

> 讲解点：
> - 取数子任务的 `result_summary` 是**真实 SQL 结果**——`数码配件 GMV 8,505,000，环比 -18.0%`，后面的归因和报告都基于这行数据，不是编的。
> - 评审不是锦上添花：5 个维度（证据/忠实/一致/完整/格式）打分，低于 3.5 会打回重做。
> - 注意「降级：是（本地规则评审）」——这是没有真实 LLM key 时的兜底，接了 DeepSeek 就是模型评分。

## 4. 场景 B：含高危动作 → 人工审批（核心，约 90 秒）

**目的**：这是整个平台最有价值的部分——**AI 能动手，但不能自己拍板动手**。

### 4.1 提交一个会被拦截的任务

| 步骤 | 操作 | 预期 |
|---|---|---|
| 4.1.1 | 回「新建任务」，点 **「含通知（触发审批）」** | 目标框填入：`分析上周 GMV 与转化率变化，归因到品类，并通知运营群` |
| 4.1.2 | 点 **「提交并开始」** | 事件控制台滚动到 `planner` 后出现 **`human_gate`**，随后 `interrupt` 事件 |
| 4.1.3 | 观察状态徽标 | 变黄 **待审批**，下方出现黄色条：`任务已挂起等待人工审批：高危动作需审批：#4 推送运营群通知` |

**完整版目标**（想要图表效果就用这段，6 个子任务）：

```
分析上周商城各大类 GMV 下滑原因，画一张环比趋势图，检索历史周报佐证，最后把结论推送到运营群
```

### 4.2 打开审批弹窗

| 步骤 | 操作 | 预期 |
|---|---|---|
| 4.2.1 | 点黄色条里的 **「立即审批」** | 弹出「审批高危动作」弹窗 |
| 4.2.2 | 指弹窗内容 | 任务号、目标、**阻断原因**、审批单号、**过期时间（24h）**，以及「高危子任务」表格 |

> 讲解话术：
> 「系统识别出 `notify` 是外发动作，一旦发错就是事故，所以在 `human_gate` 节点 `interrupt` 挂起。
> 注意这里给的是**决策所需的最小信息**：发什么、发给谁、为什么被拦、多久过期——审批人不用翻日志。」

### 4.3 通过并续跑

| 步骤 | 操作 | 预期 |
|---|---|---|
| 4.3.1 | 意见框填：`同意推送，报告结论与数据一致` | — |
| 4.3.2 | 点 **「同意并继续」** | 弹窗关闭，提示「已通过，任务继续执行」，状态回到 **进行中** |
| 4.3.3 | 等 5~10 秒 | 子任务逐个变 `DONE`，最终 **已完成** |

**终态实测数据**（6 子任务版本）：

```
子任务：取数 / 归因 / 检索历史周报 / 生成对比图表 / 汇总报告 / 推送运营群通知   全部 DONE
Token ：4018
评审  ：4.6 / 5  通过
图表  ：/static/charts/chart_90fe42240242.png
报告  ：经营分析报告（markdown）
```

**两个可以现场打开的链接**（浏览器直接访问）：

```
http://127.0.0.1:8000/static/charts/chart_90fe42240242.png     # 图表文件（你自己的任务号会不同）
http://127.0.0.1:8000/docs                                      # Swagger，显示全部 26 个接口
```

### 4.4 讲「断点续跑」这个技术点

打开详情页 → 滚到最下面的**轨迹**时间轴（tab：「步骤」）：

```
#14 planner     llm.call
#15 planner     enter
#16 planner     exit
#17 human_gate  enter        ← 在这里挂起
#38 human_gate  enter        ← 审批后从断点重新进入
#40 executor    tool.call
...
```

> 讲解话术：
> 「审批不是把任务重跑一遍。挂起时 LangGraph 的 checkpoint 停在 `human_gate`，审批后从**那一帧**继续。
> 你看轨迹里 `planner` 只出现了一次——取数和归因已经跑完的结果被 checkpoint 保住了，不会重复调模型、重复扣 token。
> 对比场景 C 的驳回就不一样了：驳回走的是 replan，会重新规划、重新执行，那是设计上的重做。」

## 5. 场景 C：驳回 → 重规划 → 安全阻断（最有说服力，约 60 秒）

**目的**：证明驳回**不是静默跳过**，而是真的拦住。

| 步骤 | 操作 | 预期 |
|---|---|---|
| 5.1 | 再提交一次「含通知（触发审批）」任务 | 同样挂在待审批 |
| 5.2 | 点「立即审批」，意见填：`结论未给出数据来源，请补充证据后再推送` | — |
| 5.3 | 点 **「驳回并重规划」** | 提示「已驳回，进入重规划」，状态回 **进行中** |
| 5.4 | 盯事件控制台 | 出现 **`replan`** 节点的 enter/exit，`replan_count` 变 **1** |
| 5.5 | 等 10~15 秒 | 状态变红 **失败** |

**实测终态**：

```
status  : FAILED
replan  : 1
error   : APPROVAL_MISSING
message : notify 前置条件不满足：审批未通过，已阻断发送
子任务  : 取数 DONE / 归因 DONE / 汇总 DONE / 推送运营群通知 FAILED
```

> 讲解话术（**建议重点讲这一段**）：
> 「很多人会担心：AI 被驳回了，会不会自作聪明绕过去偷偷发？不会。
> 驳回后系统确实重新规划了（`replan_count=1`），也重新跑完了取数和归因，但走到 `notify` 时，
> **工具层的前置条件校验发现这张审批单是 REJECTED，直接阻断**，报 `APPROVAL_MISSING`，任务失败。
> 这不是『前端藏了个按钮』，是执行链路上的硬约束。高危动作要么被批准，要么就是发不出去。」

## 6. 场景 D：终止任务（可选，20 秒）

| 步骤 | 操作 | 预期 |
|---|---|---|
| 6.1 | 提交一个较长任务（含图表 / 通知，4~6 子任务），**提交后立刻**点 **「终止任务」** | 顶部提示「已终止任务」，状态徽标变红 **已取消**（CANCELLED） |
| 6.2 | 观察事件流 | 收到 `complete` 终止帧，前端关闭 SSE 连接 |

**实测**：无延迟取消 → `status=CANCELLED`、`error.code=TASK_CANCELED`，1 秒内落终态。

> ⚠️ 演示注意：Mock 模式下整条链路只要 1~2 秒。如果点得慢了，任务已经跑完，你会看到状态是「已完成」但 `error` 里留着 `TASK_CANCELED`——这是取消请求与收尾的竞态，不是 bug。
> 想稳定复现「已取消」，用一个 6 子任务的目标（带图表 + 通知），提交后**立刻**点取消。

> 讲解点：终止会同时做三件事——写终态、清空 checkpoint 的 `next/interrupts`（防止「僵尸挂起」被后续误恢复）、释放事件队列资源。所以后面再点审批也不会把任务「复活」。

## 7. 可观测性（技术型观众加这一段，约 90 秒）

### 7.1 轨迹接口

```bash
# 把 2 换成你的任务号
curl -s -H "Authorization: Bearer <TOKEN>" \
  http://127.0.0.1:8000/api/v1/tasks/2/trace | python -m json.tool | head -40
```

返回 `steps`（节点进出、LLM 调用、工具调用）、`checkpoints`、`interrupt`、`total_steps`。

### 7.2 状态快照

```bash
curl -s -H "Authorization: Bearer <TOKEN>" \
  http://127.0.0.1:8000/api/v1/tasks/2/snapshot | python -m json.tool
```

`values` 是 LangGraph 的完整状态，包含 `plan / messages / token_ledger / replan_context`。

### 7.3 SSE 原始帧

```bash
curl -N -H "Authorization: Bearer <TOKEN>" \
  http://127.0.0.1:8000/api/v1/tasks/2/stream
```

实测帧序列：

```
: connected task_id=2 trace_id=...
retry: 3000
event: state_update
data: {"node":"planner","phase":"enter","status":"RUNNING",...}
```

> 讲解点：`retry: 3000` 是断线重连间隔；`id:` 是事件序号，前端重连时带 `Last-Event-ID` 续读，不丢帧。

### 7.4 全链路追踪（OpenTelemetry）

当前演示进程**未开启** OTel（默认 `ENABLE_OTEL=false`，零开销）。要看 tracing 需另起一个进程：

```bash
ENABLE_OTEL=true OTEL_EXPORTER=console ./.venv/Scripts/python.exe -m uvicorn app.bootstrap:app --port 8001
curl -s http://127.0.0.1:8001/observability/status | python -m json.tool
curl -s http://127.0.0.1:8001/metrics | grep -E 'mcp_calls_total|llm_tokens_total'
```

> 但注意：`app.bootstrap:app` 是**生产装配**，直连 MySQL + Redis，本机没这两个服务，任务跑不动。没有中间件时建议跳过这一段，或只讲「埋点是回调+装饰器实现，关掉零开销」这个设计点。

## 8. 命令行兜底（没有浏览器时）

一条命令跑完「登录 → 提交 → 等终态 → 打印子任务」：

```bash
cd "E:/AI_Project_Workspace/AgentFlow —— 企业级多智能体任务编排与执行平台/agentflow-platform"
./.venv/Scripts/python.exe - <<'EOF'
import json, time, urllib.request
BASE = "http://127.0.0.1:8000"

def call(m, p, b=None, tok=None):
    d = json.dumps(b).encode() if b is not None else None
    r = urllib.request.Request(BASE + p, data=d, method=m)
    r.add_header("Content-Type", "application/json")
    if tok:
        r.add_header("Authorization", "Bearer " + tok)
    with urllib.request.urlopen(r, timeout=240) as resp:
        return json.loads(resp.read().decode())

tok = call("POST", "/api/v1/auth/login", {"username": "admin_user", "password": "Passw0rd!"})["data"]["access_token"]
goal = "分析上周商城各大类 GMV 下滑原因，画一张环比趋势图，检索历史周报佐证，最后把结论推送到运营群"
tid = call("POST", "/api/v1/tasks", {"goal": goal, "time_range": {"start": "2026-10-12", "end": "2026-10-18"}}, tok=tok)["data"]["task_id"]
print("task_id =", tid)
d = {}
for _ in range(60):
    d = call("GET", f"/api/v1/tasks/{tid}", tok=tok)["data"]
    if d["status"] in ("AWAITING_APPROVAL", "COMPLETED", "FAILED", "CANCELLED"):
        break
    time.sleep(3)
print("status =", d["status"], "| token =", d.get("token_usage"))
for s in d.get("subtasks") or []:
    print(f"  #{s['seq']} {s['name']}  {s['status']}  risk={s.get('risk_level')}")
print("图表 =", [a["url"] for a in d.get("artifacts") or [] if a.get("type") == "chart"])
# 审批通过
call("POST", f"/api/v1/tasks/{tid}/resume", {"decision": "APPROVED", "comment": "同意推送", "sync": False}, tok=tok)
EOF
```

## 9. 常见问题（演示前扫一眼）

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面白屏 / 提示「Vue 3 加载失败」 | 前端 Vue 走 unpkg CDN，断网则失败 | 联网后刷新；内网环境需把 `vue.global.prod.js` 下到 `frontend/vendor/` 并改 `index.html` |
| 点「演示登录」报「登录失败」 | 后端没起 / 端口不对 | 确认 `http://127.0.0.1:8000/healthz` 返回 `{"status":"ok"}` |
| 图表 URL 打开 404 | 旧版启动脚本未挂载 `/static` | 当前版本已挂载，重启服务即可（`scripts/dev_serve.py` 会打印「已挂载 /static」） |
| 提交后一直「进行中」不结束 | 前端 SSE 断了，但后端还在跑 | 点详情页 →「刷新」；或看事件控制台是否有 `SSE error` |
| Token 过期 | access_token 有效期 120 分钟 | 重新点「用演示账号获取 Token」 |
| 想从零开始演示 | 库里有旧任务 | 停服务后 `scripts/dev_serve.py --reset` 启动 |
| 想看真实模型效果 | 当前是 Mock LLM | 需在 `.env` 配 `LLM_API_KEY` 且 `LLM_MOCK=false`；本地未验证 |
