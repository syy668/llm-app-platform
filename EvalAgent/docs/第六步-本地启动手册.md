# 第六步：三项目本地启动手册（CMD / PowerShell 双版本）

> 适用：Windows 本机、代码已在 `E:\AI_Project_Workspace`、依赖已装好（3 个 `.venv` + 4 个 `node_modules` 均存在）。
>
> **每一步都给 CMD 和 PowerShell 两版，任选一种跑，别在同一窗口混用**（差异见 §9）。  
> 端口口径：**8010 = 项目一后端**，**5175 = 项目一前端**，**8200 = 项目二后端**，**5174 = 项目二前端**，**8000 = 项目三后端**，**5173 = 项目三前端**。

## 1. 基础设施（每次开机都要做）

### 1.1 先确认 Docker Desktop 已运行，再起 Redis

两个 shell 命令一样（Docker CLI 是同一个 `docker.exe`）：

```bat
docker start redis-stack
docker ps --filter name=redis-stack
```

预期：`redis-stack  ... Up ... 0.0.0.0:6379->6379/tcp`

验证 Redis 真的可用（项目一/项目三都要求 RediSearch + RedisJSON，不只是能连上）：

```bat
docker exec redis-stack redis-cli ping
```

预期：`PONG`

> Docker Desktop 没启动时 `docker start` 会报 `cannot connect to the Docker daemon`。先手动打开 Docker Desktop，等托盘图标变绿。

### 1.2 起 MySQL 3307（项目三专用实例，最容易漏）

**开一个专用窗口，让它常驻，别关。**

**【CMD】**

```bat
"C:\Program Files\MySQL\MySQL Server 8.0\bin\mysqld.exe" --datadir=C:/Users/Public/agentflow-mysql-data --port=3307 --console
```

**【PowerShell】**

```powershell
& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysqld.exe" --datadir=C:/Users/Public/agentflow-mysql-data --port=3307 --console
```

> PS 里路径带空格必须加引号，**而且开头必须写 `&`**（调用运算符），否则 PS 只把这串路径当字符串**打印**出来，什么都不执行。

验证（另开一个窗口）：

**【CMD】**

```bat
netstat -ano | findstr :3307
```

**【PowerShell】**（比 netstat 干净，直接给 PID）

```powershell
Get-NetTCPConnection -LocalPort 3307 -State Listen | Select-Object LocalAddress,LocalPort,OwningProcess
```

预期：`TCP  0.0.0.0:3307  ...  LISTENING  <pid>`

> - 这个实例是**手工前台进程**，不是 Windows 服务，所以服务列表里看不到、开机也不回来。
> - 关掉那个窗口 = 项目三的库消失，所有任务查询立刻报连接错误。
> - 不想占窗口的话，PowerShell 可以弹一个新窗口后台跑：
>   ```powershell
>   Start-Process -FilePath "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysqld.exe" `
>     -ArgumentList "--datadir=C:/Users/Public/agentflow-mysql-data","--port=3307","--console"
>   ```
>   别用 `-NoNewWindow` 配 `--console`，日志会和你的命令输出搅在一起。

## 3. 项目一前端：知识库控制台（5175）

> **两个必须显式覆盖的地方，不覆盖就起不来或者起来也用不了：**
>
> 1. **端口**：`frontend_vue/vite.config.ts` 里写死 `server.port: 5173`，而 5173 已经是项目三前端。不加 `--port 5175` 会撞车（也不加 `--strictPort` 的话 Vite 会静默 +1 到 5174，再撞项目二）。
> 2. **API 基址**：`frontend_vue/.env.development` 里是 `VITE_API_BASE_URL=http://127.0.0.1:8000/api/v1` —— **8000 是项目三**。不改的话前端所有请求都打到 AgentFlow，表现是「登录一直转圈 / 401 / 接口 404」。
>
> 下面用**命令行注入环境变量**覆盖基址（Vite 5.4.21 的 `loadEnv`：`process.env` 里的 `VITE_*` 会覆盖 `.env` 文件里的同名值），**不动仓库里的任何文件**。

**【CMD】**

```bat
cd /d "E:\AI_Project_Workspace\企业垂直知识库 Agent 后台\frontend_vue"
set "VITE_API_BASE_URL=http://127.0.0.1:8010/api/v1" && node node_modules\vite\bin\vite.js --host 127.0.0.1 --port 5175 --strictPort
```

**【PowerShell】**

```powershell
Set-Location "E:\AI_Project_Workspace\企业垂直知识库 Agent 后台\frontend_vue"
$env:VITE_API_BASE_URL = "http://127.0.0.1:8010/api/v1"
& node "node_modules\vite\bin\vite.js" --host 127.0.0.1 --port 5175 --strictPort
```

预期输出（本机实测）：

```
VITE v5.4.21  ready in 2141 ms

➜  Local:   http://127.0.0.1:5175/
```

打开 `http://127.0.0.1:5175/`，页面标题是「企业垂直知识库 Agent 后台」，登录后落到 `/knowledge`。

验证：

**【CMD】**

```bat
curl --noproxy "*" -s -o NUL -w "%{http_code}" http://127.0.0.1:5175/
```

**【PowerShell】**

```powershell
curl.exe --noproxy "*" -s -o NUL -w "5175 -> %{http_code}`n" http://127.0.0.1:5175/
```

要点：

- `--strictPort` **必加**：端口被占时直接报错退出，而不是悄悄换端口让你以为起成功了。
- 前端是**直连后端**（`vite.config.ts` 里 proxy 那段是注释掉的，靠后端 CORS `allow_origins=*`），所以基址里 `/api/v1` 必须带全，且末尾不要多斜杠。
- `--host 127.0.0.1` 会覆盖 config 里的 `host: true`（原本会监听 0.0.0.0，局域网可访问）。
- 想不写一长串命令行、又要固定基址：新建 `frontend_vue/.env.local`，内容一行 `VITE_API_BASE_URL=http://127.0.0.1:8010/api/v1`，之后 `node node_modules\vite\bin\vite.js --port 5175 --strictPort` 就行。注意项目一 `.gitignore` 只忽略 `.env`、**不忽略 `.env.local`**，别误提交。
- 路由是 **history 模式**（`/login` `/knowledge` `/chat` `/reports` `/trace` `/eval` `/config` `/users`），和项目三的 hash 路由不同，深链直接写 `http://127.0.0.1:5175/eval`。
- **项目二前端的「打开登录页」按钮指向这里**（`VITE_LOGIN_URL`）。项目二 `.env.development` 已同步改成 `http://localhost:5175/login`，改端口时两边要一起改。

预期：


> ```powershell
> [System.Net.WebRequest]::DefaultWebProxy = $null
> ```
>
> 或者干脆用写法 A。

- `database_healthy:true` 才说明 3306 的 `eval_agent_db` 通了；`false` 就是 3306 没起或库被删（`AUTO_CREATE_TABLES=true` 只会补表，不建库）。

## 9. PowerShell 专属坑（本机 PS 5.1 实测确认）

| # | 坑                              | 现象                                                                                                                       | 正确写法                                                                                          |
| - | ------------------------------ | ------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| 1 | **`curl` 不是 curl.exe**         | PS 5.1 里 `curl` 是 `Invoke-WebRequest` 的**别名**，`curl --noproxy "*" -s` 直接 `ParameterBindingException：找不到接受实际参数"*"的位置形式参数` | 一律写 **`curl.exe`**                                                                            |
| 2 | **`cd /d` 不认**                 | `cd /d "E:\..."` → `找不到接受实际参数"E:\..."的位置形式参数`                                                                            | PS 不需要 `/d`：`Set-Location "E:\..."`（`cd` 也行）                                                  |
| 3 | **没有 `&&`**                    | `A && B` → **解析错误** `标记"&&"不是此版本中的有效语句分隔符`（5.1 通病，`try/catch` 都拦不住，整行不执行）                                                | 顺序执行用 `A; B`；要判上一步成功用 `A; if ($?) { B }`                                                      |
| 4 | **路径带空格要 `&`**                 | `"C:\Program Files\...\x.exe" -arg` 只把这串**打印**出来，不执行                                                                     | `& "C:\Program Files\...\x.exe" -arg`                                                         |
| 5 | **代理会劫持 127.0.0.1**            | `Invoke-RestMethod` 报 `无法连接到远程服务器`，但服务是好的（系统代理 / `HTTP_PROXY` 生效）                                                        | curl.exe 加 `--noproxy "*"`；或 `[System.Net.WebRequest]::DefaultWebProxy = $null`               |
| 6 | **`%` 是 `ForEach-Object` 的别名** | `-w %{http_code}` 行为诡异                                                                                                   | 放进引号：`-w "%{http_code}"`（PS 里**不用**像 .bat 那样双写 `%%`）                                          |
| 7 | **venv 激活不是必需的**               | `Activate.ps1` 可能被执行策略拦（本机 `CurrentUser=RemoteSigned`，能跑；换机器可能被拦）                                                        | 直接调 `& ".\.venv\Scripts\python.exe"`，跳过激活最稳；非要激活先 `Set-ExecutionPolicy -Scope Process Bypass` |
| 8 | **`Ctrl+C` 只停当前前台**            | `Start-Process` 起的服务在自己窗口里，本窗口 Ctrl+C 停不掉                                                                                | 去那个窗口按 Ctrl+C，或按 PID 停（见 §11）                                                                 |
| 9 | **`$PID` 是保留变量**               | `$pid = ...` 报只读错误                                                                                                       | 换名：`$procId`                                                                                  |

## 11. 关闭顺序（反向）

1. `5175` / `5174` / `5173` 三个 Vite（各自窗口 Ctrl+C）
2. `8000` 项目三后端
3. `8200` 项目二后端
4. `8010` 项目一后端
5. 3307 那个 mysqld 窗口（**先关应用再关库**，避免 `eval_runs`/`tasks` 卡在中间态）
6. `docker stop redis-stack`（可留，下次开机会更快）

按端口强停（**只在确认那个进程是自己起的项目服务时才用**）：

**【PowerShell】**

```powershell
$port = 8000
$procId = (Get-NetTCPConnection -LocalPort $port -State Listen -ErrorAction SilentlyContinue).OwningProcess
if ($procId) {
  Get-Process -Id $procId | Select-Object Id,ProcessName,StartTime   # 先确认再杀
  # Stop-Process -Id $procId -Force
}
```

> 注意别用 `$pid` 当变量名——`$PID` 是 PowerShell 的**保留自动变量**（当前进程 ID），赋值会报只读错误。

> 若中途直接杀掉后端进程，项目一会留下 `eval_runs` 永久 `running`（占满并发闸），项目三会留下 `RUNNING` 任务。  
> 项目一回收：`cleanup_stale_running_runs(max_age_seconds=300)`；项目三超时审批由 300s 定时器兜底。

## 附录 A：PowerShell 一键后台拉起（每服务一个独立窗口）

不想开一堆窗口逐个贴命令，用这个（**先确保 §1 基础设施已就绪**；项目一前端因为要注入 env，单独见附录 B）：

```powershell
$w  = "E:\AI_Project_Workspace"
$p3 = "$w\AgentFlow —— 企业级多智能体任务编排与执行平台"
$tasks = @(
  @{ Dir = "$w\企业垂直知识库 Agent 后台";
     Exe = "$w\企业垂直知识库 Agent 后台\.venv\Scripts\python.exe";
     Arg = @("-m","uvicorn","app.main:app","--host","127.0.0.1","--port","8010") },
  @{ Dir = "$w\EvalAgent\evalagent_backend";
     Exe = "$w\EvalAgent\evalagent_backend\.venv\Scripts\python.exe";
     Arg = @("-m","uvicorn","app.main:app","--host","127.0.0.1","--port","8200") },
  @{ Dir = "$w\EvalAgent\evalagent_vue";
     Exe = "node";
     Arg = @("node_modules\vite\bin\vite.js","--host","127.0.0.1","--port","5174","--strictPort") },
  @{ Dir = "$p3\agentflow-platform";
     Exe = "$p3\agentflow-platform\.venv\Scripts\python.exe";
     Arg = @("-m","uvicorn","app.main:app","--host","127.0.0.1","--port","8000") },
  @{ Dir = "$p3\agentflow-web";
     Exe = "node";
     Arg = @("node_modules\vite\bin\vite.js","--host","127.0.0.1","--port","5173","--strictPort") }
)

foreach ($t in $tasks) {
  $p = Start-Process -FilePath $t.Exe -ArgumentList $t.Arg -WorkingDirectory $t.Dir -PassThru
  "port={0,-6} PID={1,-6} {2}" -f $t.Arg[-1], $p.Id, $t.Dir
}
```

要点：

- `-WorkingDirectory` **必须给**，否则 uvicorn 找不到 `app.main`、vite 找不到 `node_modules`。
- 每个服务一个新窗口，日志在各自窗口里；关窗口 = 停服务。
- `-PassThru` 打出 PID，方便收摊：
  ```powershell
  Get-Process python,node | Select-Object Id,ProcessName,StartTime
  ```
  别把**别的项目**的 python/node 一起杀了——按 `StartTime` 和窗口标题认。

> 项目二后端（8200）建议**单独手动起在前台**：启动时它会打数据库自检和裁判模型 preflight 结果，这些日志是第一手排障信息。

## 附录 B：PowerShell 后台起项目一前端（要带环境变量）

PS 5.1 的 `Start-Process` **没有 `-Environment`**（PS 7+ 才有），所以先设父进程变量 → 拉起 → 立刻还原：

```powershell
$w = "E:\AI_Project_Workspace"
$old = $env:VITE_API_BASE_URL
$env:VITE_API_BASE_URL = "http://127.0.0.1:8010/api/v1"
Start-Process -FilePath $env:ComSpec `
  -ArgumentList "/k","node node_modules\vite\bin\vite.js --host 127.0.0.1 --port 5175 --strictPort" `
  -WorkingDirectory "$w\企业垂直知识库 Agent 后台\frontend_vue"
$env:VITE_API_BASE_URL = $old
```

要点：

- 用 `cmd /k` 起，变量在**子进程创建那一刻**被继承，所以 `Start-Process` 之后立刻 `$old` 还原是安全的；`/k` 让窗口常驻，日志看得见。
- 不要在**当前窗口**直接 `$env:VITE_API_BASE_URL=...` 然后就跑项目三前端——项目三的 `VITE_API_BASE_URL` 本来是空字符串（走 Vite 同源代理），被污染后它会直连 8010 且丢掉 `/api/v1` 前缀。
- PowerShell 7 用户可简化成一行：
  ```powershell
  Start-Process node -ArgumentList "node_modules\vite\bin\vite.js","--host","127.0.0.1","--port","5175","--strictPort" `
    -WorkingDirectory "$w\企业垂直知识库 Agent 后台\frontend_vue" `
    -Environment @{ VITE_API_BASE_URL = "http://127.0.0.1:8010/api/v1" }
  ```
