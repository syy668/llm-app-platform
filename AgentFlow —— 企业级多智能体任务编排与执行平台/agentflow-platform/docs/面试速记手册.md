# AgentFlow 求职面试速记手册（Cheat Sheet）

> **封版基线**：v1.2+ · 610 个测试全绿 · 10 轮加固收官。
> 用法：面试前 30 分钟过一遍，每条都是"要说出口的话"，不是代码文档。

---

## 模块 1：一句话介绍项目

> **电梯陈述（30 秒版）**

AgentFlow 是一个**企业级多智能体任务编排平台**：用户给一句业务目标，系统自动拆解成子任务、调用企业自有知识库等工具、由独立的评审智能体逐级打分把关，产出**可追溯、可干预、可复盘**的结论。

它解决三个真金白银的痛点：**通用大模型不懂企业内部资料**（接企业知识库解决）、**AI 产出没人把关**（评审节点 + 可信度解决）、**任务失败只能从头重跑**（Redis 断点持久化 + 人工批注重规划解决）。

工程底座经得起追问：**7 类智能体分工协作、10 轮防御性加固、610 个测试全绿**的封版交付。

## 模块 2：业务应用场景与核心价值

### 能落地的真实场景

1. **企业运维知识问答**：把运维手册、故障案例接进知识库，员工提问 → 智能体检索 → 评审 → 给出贴合业务的处理方案（如"查上个月服务器宕机的处理方案并出报告"）。
2. **业务数据查询**：自然语言 → SQL 工具查业务库 → 自动汇总，业务人员不用写 SQL 也能拿数。
3. **文档检索与报告生成**：从企业文档库精准检索片段作为证据，自动生成周报/总结类报告。
4. **自动化任务流水线**：周期性、标准化的"查资料 → 出结论 → 通知"流程，全程无人值守，高风险动作自动转人工。

### 对比传统方案，优势在哪

| 对比维度 | 单体 AI / 人工操作 | AgentFlow |
|---|---|---|
| 知识来源 | 只会公共大模型，不懂内部资料 | 外接企业垂直知识库（RAG），答案有出处 |
| 质量控制 | 一次性输出，错了没人发现 | 评审节点逐子任务打分算可信度，低分自动拦下 |
| 失败成本 | 从头重跑，费时费钱 | 断点持久化，中断/重启后从断点续跑 |
| 风险管控 | 工具裸奔，想关关不掉 | 工具注册表热启停 + 限流 + 高危操作人工闸门 |
| 沉淀复盘 | 聊完即散，无迹可寻 | 全程轨迹落库，服务端一键导出归档；分层记忆越用越懂业务 |

## 模块 3：核心业务流转链路（大白话版）

**用户输入**："帮我查一下上个月服务器宕机的处理方案，并生成一份总结报告。"

1. **Planner（规划师）**：把这句话拆成有先后依赖的子任务 DAG，比如「① 检索宕机处理记录 → ② 汇总生成报告」。拆解时会注入两样东西：**分层记忆命中**（≤3 条历史相关经验，越用越准）和**当前已启用的工具清单**（被禁用的工具规划师根本看不到）。

2. **Executor（执行员）**：逐个子任务挑工具执行——这里调 `kb-search` 走 MCP 协议到项目一知识库做检索。失败会重试/降级；工具报错会先"瘦身"（≤200 字、去掉堆栈）再进上下文，防止错误信息污染下游智能体。

3. **Reviewer（评审员）**：对执行结果做**服务端裁决 = 分数 + 证据覆盖度 + 来源系数 → 可信度**。判 REJECT 不直接失败，而是进入人工闸门：任务挂起为 `AWAITING_APPROVAL`，人在收件箱填批注驳回，**批注作为硬约束交给 Planner 重规划**，新子任务严格跟着批注变。这正是"带环的状态机"——评审打回重写。

4. **Summarizer（总结员）**：把各子任务结果汇总成最终报告；检索不到就诚实报 `NO_DATA_FOUND` 而不是编造。高分结论归档进长期记忆，全程轨迹落库，可一键导出 JSON 复盘。

## 模块 4：硬核技术栈与架构设计（选型理由版）

- **FastAPI**：全异步 + 原生 SSE 支持。多智能体执行动辄几十秒，流式推送是体验刚需，FastAPI 是异步生态里成本最低的路径。

- **LangGraph**：因为需要**带环的状态机**——"评审打回 → 重规划"在图上是个环；且官方 checkpointer 天然支持 interrupt/resume，断点续跑不用自己造轮子。

- **Redis Stack（不是普通 Redis）**：一身五职——① 限流计数（INCR+EXPIRE 固定窗口）② 分布式锁（防并发重复 resume/cancel）③ **断点持久化**（AsyncRedisSaver 依赖 RediSearch + RedisJSON，普通 Redis 会静默降级成内存模式，重启丢审批断点——这是生产事故级别的坑）④ 短期记忆 ⑤ 工具注册表。

- **MySQL**：任务/子任务/审批/轨迹/记忆 8 张表。全库统一 **UTC naive** 时间口径（连接层 `SET time_zone='+00:00'` 兜底），否则跨时区写时间会算出负耗时、日志慢 8 小时——我们真踩过并修掉了。

- **ContextVars**：task_id 的异步上下文隔离。日志格式化器自动带 `[task_id:N]`，分布式排障不用人肉串日志，且两条执行路径零侵入接入。

- **MCP**：工具统一接入协议 + 注册表治理。`kb-search` 等工具可热启停，工具治理与执行逻辑解耦。

- **Pydantic v2 StrictModel**：智能体之间 I/O 强类型契约（`agent_io.py` 是唯一契约文件），LLM 输出额外配四级解析兜底，脏数据进不了状态机。

- **Docker Compose**：healthcheck 门控启动顺序（MySQL/Redis 就绪才起后端），alembic 先迁移再服务，冷启动幂等。

- **前端 Vue3 + TS + Vite + AntV X6**：X6 专门用来渲染子任务 DAG 图，执行进度可视化。

## 模块 5：5 个防御性亮点（面试高频考点）

> 10 轮加固构成：7 项架构师加固（分布式锁 / 工具熔断 / 限流增强 / Redis TTL 清理 / 流式导出 / 解析兜底 / 日志追踪）+ Token 硬熔断 + 提示词注入防御 + 防御口径统一补丁。

1. **【提示词注入】** 知识库文档被投毒，诱导智能体泄露 System Prompt 或越权执行
   → **【三道防线】** 入口层：越狱正则 + 意图组合识别（`IntentGuardrail`，直接 400 拦截）；传输层：所有喂给模型的外部内容强制 `wrap_untrusted` XML 标签**物理隔离**，并剥除内容中的同名标签防逃逸；提示层：4 个 System 注入"不可信内容"声明。

2. **【重试风暴 / 成本失控】** 大模型反复报错导致无限烧钱
   → **【单任务 Token 硬熔断】** Redis 计数（INCRBY + TTL 24h），单任务超 5 万 token 直接熔断；熔断异常**绕过主备降级逻辑**（继承业务异常基类），保证"停得下来"而不是切到备用模型接着烧；再加 30 秒硬超时 + 单次输出 2048 上限 + 启动时配置自检告警。

3. **【并发竞争】** 同一任务被并发 resume / cancel，重复执行导致状态错乱
   → **【Redis 分布式锁】** 关键路径全部包 `task_lock`；配合 Redis 键统一 TTL + 终态清理任务，防 key 无限膨胀。

4. **【雪崩与解析脆断】** 下游工具抖动引发雪崩；LLM 输出不是合法 JSON 导致流程脆断
   → **【工具三件套 + 四级解析】** 工具级超时/重试/熔断器；LLM 输出四级解析兜底（严格模型 → 宽松提取 → 修复 → 降级）；喂给模型的错误信息强制 ≤200 字去堆栈，防上下文污染与内部信息泄露。

5. **【流量洪峰 & 导出 OOM】** 多人并发压垮服务；超长任务导出撑爆内存
   → **【四类配额限流 + 流式导出】** 按接口类型分池限流（API 300 / LLM 30 / KB 60 / 单任务 240 每分钟），超限 429 带 `Retry-After`，健康检查白名单放行；另加用户日配额 + LLM 令牌桶；导出走 `StreamingResponse` 流式输出，轨迹上限 2000 条防卡死浏览器。

## 模块 6：项目局限性（坦诚局）

**局限性一：长文本处理偏粗暴。**
LLM 上下文在入口统一按 12000 字符**硬截断**，长文档可能被"腰斩"，中间的关键信息会丢。没有动态摘要、没有按重要性压缩。
→ **v4.0 演进**：上下文预算动态分配 + map-reduce 分层摘要，用分层记忆做"重要片段召回"替代一刀切截断——记忆系统的基础设施已经在了，缺的是接上压缩策略。

**局限性二：评审可信度是规则启发式，未做校准。**
Reviewer 的裁决 = 分数 + 证据覆盖度 + 来源系数，优点是**可解释、零成本**，但阈值靠经验设定，没有用真实数据校准过，边界 case 可能误判。
→ **v4.0 演进**：引入可插拔小模型做校准评分（架构上已预留插槽，意图识别护栏就是这个思路），用评测集回归验证阈值后再灰度替换规则。

**面试收尾话术**："这两个局限我都在设计时就知道，并且留了演进插槽——我认为知道系统边界在哪，比假装没有边界更重要。"
