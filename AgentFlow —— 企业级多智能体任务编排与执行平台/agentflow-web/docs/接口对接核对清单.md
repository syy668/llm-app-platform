# AgentFlow 前端 ↔ 后端 接口对接核对清单

> 用途：联调时逐条打勾。所有接口均来自后端 `app/routers/*.py` 的实际路由，
> **没有虚构任何接口、入参或返回字段**。字段名严格使用后端出参原样（如 `task_id` 而非 `id`）。
>
> 最后更新：2026-10-22 · 对应前端 `agentflow-web@1.0.0`（v1.0 缺口收口后）

---

**说明②** 抽屉展示的挂起上下文统一用 `GET /tasks/{id}/interrupt`（含 `reason` / `preview` / `next_node` / `resumable`），
比 `GET /approvals/{id}` 多了"是否可恢复"与"后续节点"；后者已封装但当前页面未调用。

## 3. SSE 事件契约核对（`GET /tasks/{id}/stream`）

公共信封：`task_id`、`trace_id`、`seq`、`node`、`ts`、`elapsed_ms`

| 事件 | 触发 | 前端使用字段 | 核对 |
|---|---|---|---|
| `state_update` | `phase=run` | `status`、`mode`（fresh/resume） | ☐ |
| | `phase=enter` | `node` → DAG 节点置「执行中」 | ☐ |
| | `phase=exit` | `node`、`status`、`output_keys` → 节点置「完成」 | ☐ |
| | `phase=error` | `node`、`error` → 节点置「失败」+ 顶部异常提示 | ☐ |
| | `phase=cancel_requested` | `status=CANCELLED` | ☐ |
| `tool_call` | `phase=call` | `tool`、`server`、`params` → Tab1 实时工具列表 | ☐ |
| | `phase=result` | `ok`、`latency_ms`、`error_code`、`result_digest` | ☐ |
| `interrupt` | 审批挂起（**终帧**） | `approval_id`、`type`、`reason`、`preview`、`next_node`、`resumable` → 自动开抽屉 | ☐ |
| `complete` | 任务终态（**终帧**） | `status`、`token_usage`、`artifacts`、`degraded`、`replan_count`、`elapsed_ms` | ☐ |

注意事项：
- 令牌通过 `?access_token=` 传递（EventSource 无法设置请求头）。
- 收到终帧必须 `close()`，否则浏览器会自动重连。
- 心跳是注释帧 `: ping`，不触发 message 事件，前端无需处理。

## 4. 错误码分支核对

| code | HTTP | 前端处理 | 位置 |
|---|---|---|---|
| `OK` | 200 | 解包 `data` | `api/http.ts` |
| `AUTH_INVALID_CREDENTIALS` | 401 | "用户名或密码错误"，清空密码并聚焦（**不提示"用户不存在"**） | 登录页 |
| `AUTH_USER_DISABLED` | 403 | "账号已被禁用，请联系管理员" | 登录页 |
| `AUTH_TOKEN_EXPIRED` | 401 | 静默 refresh 后重放一次 | 拦截器 |
| `AUTH_TOKEN_MISSING` / `INVALID` / `REVOKED` / `AUTH_REFRESH_REVOKED` | 401 | 清 token，跳 `/login?redirect=` | 拦截器 |
| `FORBIDDEN` | 403 | 提示"当前角色无权执行该操作"；审批时额外提示"不能审批本人任务" | 详情/收件箱 |
| `NOT_FOUND` | 404 | `StateBlock state="error"` + 重试 | 详情页 |
| `VALIDATION_ERROR` / 422 | 422 | 提示"入参未通过后端校验" | 新建任务 |
| `SERVICE_UNAVAILABLE` | 503 | 记忆未启用等场景提示开关名 | 记忆页 |
| `STREAM_DISABLED` | 503 | SSE 关闭，页面降级为轮询详情 | 详情页 |
| `NETWORK_ERROR` | — | "无法连接后端服务" + 回显 API 地址 | 全局 |

## 6. 联调自检命令

```bash
# 1) 探针
curl -s http://127.0.0.1:8000/healthz
curl -s http://127.0.0.1:8000/readyz
curl -s http://127.0.0.1:8000/api/v1/health

# 2) 登录（记下 access_token）
curl -s -X POST http://127.0.0.1:8000/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"ops_zhangsan","password":"***"}'

# 3) 角色（唯一来源）
curl -s http://127.0.0.1:8000/api/v1/auth/me -H "Authorization: Bearer $TOKEN"

# 4) 建任务（流式入口，仅 admin）
curl -s -X POST http://127.0.0.1:8000/api/v1/tasks/stream \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"goal":"分析 2026 年 9 月女装类目 GMV 环比下滑原因","time_range":{"start":"2026-09-01","end":"2026-09-30"},"sync":false}'

# 5) SSE（浏览器端会自动加 ?access_token=）
curl -N "http://127.0.0.1:8000/api/v1/tasks/1024/stream?access_token=$TOKEN"

# 6) 审批
curl -s -X POST http://127.0.0.1:8000/api/v1/tasks/1024/resume \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"decision":"APPROVED","comment":"同意，缩小到近 7 天"}'
```

## 7. 联调时最容易踩的 5 个坑

1. **401 与 403 不要混用文案**：账号不存在与密码错误必须是同一句"用户名或密码错误"（后端 `dummy_verify` 抹平了时序差异）。
2. **`depends_on` 存的是 `seq` 不是 `id`**：DAG 连线用 seq，点查详情用 id。
3. **没有 `duration` 字段**：耗时永远前端算；SSE `complete.elapsed_ms` 只用于终态校准。
4. **`artifacts[].url` 是 `/static/...` 相对路径**：需要拼 `VITE_API_BASE_URL`，否则图片 404。
5. **viewer 的详情字段被裁剪**：没有 `creator_id`，`subtasks` 只剩 `seq/name/tool_hint/status/risk_level`；
   前端所有读取这些字段的地方都做了容错（`?.` + 默认值）。
