## 一、路由覆盖（7 条，全部实测通过）

`route` 不在 chat 响应里，落在 `messages.agent_route`；前端看 AI 气泡上的标签，后端查 `GET /conversations/{id}/messages`。

| # | 提问 | 预期路由 | 触发原因 |
|---|---|---|---|
| R1 | 如何申请服务器权限？ | `rag` | 含「如何」→ 规则短路，不走 LLM |
| R2 | 公司 VPN 账号锁定了怎么办 | `rag` | 含「怎么办」→ 规则短路 |
| R3 | 帮我统计一下本周的工单数量 | `report` | 含「统计」→ 报表节点，直接产 Markdown |
| R4 | 现在有多少台设备需要更换 | `db_query` | 含「多少台/设备」→ 查业务库 |
| R5 | 对比研发部和销售部的住宿标准 | `parallel_compare` | 含「对比」→ 两线程并行检索 |
| R6 | 你好，介绍一下你自己 | `direct` | 无内部知识特征 → 直接回答 |
| R7 | **如何统计本周的告警数量** | `report` | 含「如何」但含「统计」→ 不短路，判 report |

**R7 是路由优先级的关键用例**：`_NON_OPERATIONAL_RE`（报表|统计|汇总|对比|比较）会否决「如何/怎么」的规则短路，否则「如何统计」会被误判成 rag。

**必做实验**：在对话页「参数配置」里关掉「知识库检索」开关，重问 R1 → 路由应回退 `direct`（`route_condition` 的 `route_enabled` 分支），且不报错。

## 六、负例拒答（4 条，防编造）

| # | 提问 | 预期行为 | 实测结论 |

## 十、实测出的 3 个真实短板（务必记住，别被问穿）

这 3 条是我跑出来的，不是推测。面试时**主动交代**比被问出来强得多。

| 短板 | 实测现象 | 一句话解释 |
|---|---|---|
| **同名词跨体系漏召回** | 问「P1 响应时限」，doc14 的故障 P1（5 分钟）命中，doc6 的工单 P1（15 分钟）**没进 top5** | 因为 doc6 的块 3 被「工单分级」整段承载，与「P1 响应时限」的字面重合度低于 ORA 手册的速查表 |
| **短块排序偏高** | 问「远程办公几天」，doc12 块 2（**只有 388 字、无天数**）排第 1，doc9（有 3 天/8 天）排第 2 | 短块在字符级打分里占比有利，rerank 模型若未开启则纠正不过来 |
| **负例无法用分数区分** | 「年会预算」top1 = 0.0320，正例题 top1 = 0.0328 | 本地关键词向量库的分数分布不区分「相关」与「同域但不相关」，拒答必须放生成层 |

对应改进方向（都还没做）：① 同义词/实体词典把「P1-工单」「P1-故障」拆成不同实体；② 接入真实 rerank 模型（bge-reranker）替代阈值法；③ 生成层加「依据溯源 + 无依据拒答」约束。
