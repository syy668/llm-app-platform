# AgentFlow Platform — W1~W4 项目总览与总结

> 企业级多智能体任务编排与执行平台。
> 技术栈：FastAPI + LangGraph + MCP（stdio）+ Vue3（无构建）+ MySQL/Redis + SQLite/fakeredis（离线档位）。
> 本文档回答三个问题：**目录长什么样**、**已经做完什么**、**还差什么（P2）**。

## 5. 设计上的三条主线（为什么这么写）

1. **一切可降级**：LLM（mock/real）、外部 RAG（mock/HTTP/mall 兜底）、外部评测（mock/HTTP）、
   事件总线（Redis/进程内）、checkpointer（Redis/内存）—— 任何外部依赖挂掉都不阻塞主流程，只降级。
   > 代价是必须区分「降级后的结论可用性」，所以 W4 把「离线指标不可引用」写在报告第一屏。
2. **状态机是唯一事实源**：任务状态、审批单状态、checkpoint、trace 四者口径必须对齐；
   挂起判定只认快照 `interrupts`，取消要清挂起 + 过期审批单 + 保留快照（冻结 ≠ 删除）。
3. **可复现优先于聪明**：所有脚本共用 `w4_common.EmbeddedEnv`，固定 seed、固定夹具、固定口径；
   A/B 实验宁可自己重算 token 口径，也不直接相减两个不同源的数字。

| P2-7 | 前端报告导出 / 指标看板 | MVP 4 页，无导出 | 非核心链路 | 低 |
| P2-8 | 多租户与配额 | 单租户 | 产品定义 | 低 |
| P2-9 | 真实 LLM 下的 A/B 结论 | 离线只验证管线 | API Key + 真实 judge | **高（唯一挡住"对外可引用结论"的项）** |
| P2-10 | `--live` / `--require-redis` 联调验证 | 参数已实现，未在真服务跑 | 联调窗口 | 高 |

## 7. 项目总结（三句话）

1. **能力闭环了**：从「用户提交一句目标」到「多智能体拆解执行 → 高危动作人工审批 → 断点续跑 → 报告 + 轨迹回放」，
   全链路可跑、可观测、可干预、可回放；150 条用例守住 W1~W3 不回归。
2. **质量可度量了**：30 条分层难例 + 3 条种子硬断言 + 20 断点抽样 + 压缩 A/B，
   把「感觉能跑」变成了「有数可查」；同时诚实地标出「离线指标不可引用」这条边界。
3. **还差一步到生产**：P2-9（真实模型复跑）与 P2-10（真服务联调）是唯一挡在「对外可引用结论」前面的两项，
   其余 P2 属于能力扩展（MCP HTTP、分层记忆、多租户），不阻塞当前形态上线。
