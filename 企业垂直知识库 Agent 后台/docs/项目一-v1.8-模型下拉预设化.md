# 项目一 v1.8：模型下拉改为「服务商预设驱动」

> 触发点：配置页「模型」下拉只有 `deepseek-chat` / `deepseek-reasoner` 两项，
> 而输入框里显示的是 `deepseek-ai/DeepSeek-V3`——一个不在候选里的值，看着像坏掉了。

## 1. 现象与根因

现象（截图反馈）：`运行模式 = openai — OpenAI 兼容接口`，模型框里显示
`deepseek-ai/DeepSeek-V3`，点开下拉却只有两个 DeepSeek 官方模型。

根因是三处不一致叠加：

| 层 | 实际状态 | 说明 |
|---|---|---|
| 后端配置值 | `llm_api_base=https://api.siliconflow.cn/v1`、`llm_model=deepseek-ai/DeepSeek-V3` | 管理员上次确实按硅基流动填过，`data/system_config.json` 里有覆盖值 |
| 后端元数据 | `provider_presets` 已下发 3 家 × 2 个模型 | `runtime_config._PROVIDER_PRESETS`（deepseek / siliconflow / modelscope），`GET /system/config` 每次都带 |
| 前端页面 | 只写了 2 个 `<el-option>`，**从未读取 `provider_presets`** | `src/views/SystemConfig.vue` 硬编码；`src/api/system.ts` 连类型都没声明 |

所以不是「只能配两个模型」，而是**页面把后端已经准备好的候选列表丢掉了**。
Element Plus 的 `el-select` 遇到 `v-model` 值不在选项中时会原样显示该字符串，
于是出现了「显示 V3、下拉只有 chat/reasoner」的错位感。

顺带说明：下拉本身是 `filterable + allow-create`，直接键入 `qwen-max` 之类
任意模型名一直可用，只是没有任何提示告诉用户「可以自己打」。

## 2. 改动（2 个文件，纯前端）

### 2.1 `frontend_vue/src/api/system.ts`

补 `ProviderPreset` 接口（与后端 `_PROVIDER_PRESETS` 字段一一对应）+ `SystemConfig.provider_presets?`。
后端某些版本不下发时该字段可缺省，页面回退内置两项。

### 2.2 `frontend_vue/src/views/SystemConfig.vue`

1. **`presets` ref**：`applyConfig` 里读 `data.provider_presets`，非数组则留空。
2. **`currentPreset` computed**：把 `llm_api_base` 去尾斜杠、转小写后与预设比对，
   命中即认为「当前用的是这家」。这样硅基流动地址会自动识别出来。
3. **`modelOptions` computed**：候选顺序 =
   命中预设的模型 → 其它预设的模型 → 内置 `deepseek-chat`/`deepseek-reasoner` →
   当前已保存的自定义模型名（最后这步很关键，否则自定义值在列表里没有对应项）。
   已知模型附中文注解（如 `deepseek-ai/DeepSeek-V3（DeepSeek-V3 通用）`），未收录的照原样显示。
4. **「服务商预设」按钮条**：DeepSeek / 硅基流动 / 魔搭 三个按钮，当前命中的一家高亮。
   点击 `applyPreset()`：切 `llm_provider='openai'` → 写 `llm_api_base` →
   模型名不在该家候选里则取首个推荐模型 → 提示「记得点保存」。
   **只改表单不落库**，与页面其它字段的「保存后生效」口径一致，避免误点改掉线上配置。

按当前数据，改完之后下拉是 4 项（V3 / Qwen2.5-72B / deepseek-chat / deepseek-reasoner），
按钮条上「SiliconFlow 硅基流动」为选中态。

## 4. 顺手记下的口径

- `llm_provider` 与「服务商」是两个维度：前者是**协议栈**（mock / openai / anthropic），
  后者只是同一协议下的**地址+模型组合**。所以预设里没有 anthropic 分支，
  点预设等价于「选 openai 协议 + 填这家地址」。
- `provider_presets` 是**只读元数据**，`PUT /system/config` 传它会被忽略（已有用例覆盖），
  前端也不该把它加进 `PAGE_KEYS`，否则「恢复默认」会误删。
- 预设里的 `api_base` / 模型名是厂商公开文档的通用值，厂商改名或换域名需人工核实，
  所以页面保留手工改写 + 自由输入两条路，预设只当快捷方式。
