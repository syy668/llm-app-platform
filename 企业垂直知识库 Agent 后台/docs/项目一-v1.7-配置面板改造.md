### 1.2 `app/llm/factory.py`：抽 `_create_model` + 新增 `get_eval_chat_model`

原来 `get_chat_model` 内部「解析配置 → 算签名 → 查缓存 → 构造实例」四段耦合。若评测侧再写一遍
`ChatOpenAI(...)`，工厂就又退回到「多处各自为政」的老问题。因此**只把后两段抽出来**：

```diff
+def _create_model(provider, model, api_base, api_key, temperature,
+                  timeout, max_retries, *, purpose="chat") -> BaseChatModel:
+    """按配置签名缓存并构造实例（provider 分发）。"""
+    signature = _signature(provider, model, temperature, api_base, api_key, timeout, max_retries)
+    cached = _cache.get(signature)
+    if cached is not None:
+        return cached
+    instance = MockChatModel() / ChatOpenAI(...) / ChatAnthropic(...)   # 原逻辑原样搬入
+    _cache[signature] = instance
+    return instance
```

`get_chat_model` 只剩「解析」一段，行为与签名**逐字节不变**（原 256 例全绿即证据）。

新增的评测入口：

```python
def get_eval_chat_model(*, temperature=0.0, timeout=None, max_retries=None) -> BaseChatModel:
    eval_model = _optional_override("eval_llm_model")
    if not eval_model:
        # 向后兼容主路径：与 v1.6 完全一致的取值链路（连缓存实例都是同一个）
        return get_chat_model(purpose="eval", temperature=temperature,
                              timeout=timeout, max_retries=max_retries)

    provider = get_provider()                                  # provider 始终与全局一致
    api_base = _optional_override("eval_llm_api_base") or _api_base()
    api_key = "" if provider == "mock" else (_optional_secret("eval_llm_api_key") or _api_key())
    timeout = float(settings.eval_llm_timeout if timeout is None else timeout)
    max_retries = int(settings.eval_llm_max_retries if max_retries is None else max_retries)
    return _create_model(provider, eval_model, api_base, api_key,
                         float(temperature), timeout, max_retries, purpose="eval")
```

三条设计口径：

1. **判据是 `eval_llm_model`，不是 base/key**。只填了 base 或 key 而没填模型名 → 整组忽略，
   避免「模型还是 deepseek-chat、地址却指向硅基流动」这种必然 404 的错配；
2. 模型名填了但 base/key 没填 → **按字段回退**全局值，允许「同厂商换模型」的最常见场景；
3. provider 不拆分。评测若走另一个协议栈，需要另一套 SDK 分支，不属于「极小改动」。

## 4. 兼容性与回滚

- **不改配置 = 行为不变**：`eval_llm_model` 为空时走原链路，连缓存实例都复用同一个，
  评测结果与 v1.6 逐字节一致；
- **不改 `.env` = 无需迁移**：新键默认空串，老配置文件里没有这三个键也能正常加载；
- **回滚**：三个新键与 UI 都可整体移除，后端只依赖 `get_eval_chat_model` 一个入口，
  把它改回 `get_chat_model(purpose="eval")` 即回到 v1.6；
- **已知边界**：provider 不可为评测单独指定（同一进程只能有一条 SDK 分支）；
  `EVAL_LLM_TIMEOUT` / `EVAL_LLM_MAX_RETRIES` 仍只在 `.env`；
  mock 模式下评测指标无真实语义，切真实 Provider 前不要对外展示 RAGAS 数值。

## 5. 演示口径（面试可用）

> 「配置页分三层：**运行模式**决定走哪条链路，**对话模型**决定生成用谁，**评测判分模型**可选地
> 决定打分用谁。三层解耦之后有两个直接收益：一是不会再出现『页面填了 Key 却还在跑 Mock』——
> 因为 provider 现在是显式可见、且 mock 下输入框会置灰；二是评测可以做**交叉判分**，
> 用 A 模型生成、B 模型打分，避免生成模型自己给自己打高分的自评偏差。
> 默认留空即复用对话模型，所以这套改造对历史数据和行为零影响。」
