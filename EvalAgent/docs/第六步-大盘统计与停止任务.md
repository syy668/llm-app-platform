## 二、后端 diff（关键片段）

### 1. 统计接口（`GET /eval/runs/stats`）

```python
@router.get("/stats", summary="任务大盘统计（总数 / 成功率 / 平均忠实度 / 累计 Token）")
def run_stats(dataset_id: int | None = Query(None), db: Session = Depends(get_db)):
    scope = [EvalRun.dataset_id == dataset_id] if dataset_id is not None else []
    status_rows = db.execute(
        select(EvalRun.status, func.count()).where(*scope).group_by(EvalRun.status)
    ).all()
    counts = {status: int(n) for status, n in status_rows}
    total, done = sum(counts.values()), counts.get(RUN_DONE, 0)

    # 样本级均值：分母是「真实算出分的样本」，不是「跑了几个任务」
    avg_row = db.execute(
        select(func.avg(EvalScore.faithfulness), func.count(EvalScore.faithfulness))
        .join(EvalRun, EvalRun.id == EvalScore.run_id)
        .where(EvalRun.status == RUN_DONE, EvalScore.faithfulness.is_not(None), *scope)
    ).one()

    tokens, cost = db.execute(
        select(func.coalesce(func.sum(EvalRun.total_tokens), 0),
               func.coalesce(func.sum(EvalRun.cost_usd), 0)).where(*scope)
    ).one()

    return ok({
        "total_runs": total, "done_runs": done,
        "failed_runs": counts.get(RUN_FAILED, 0),
        "cancelled_runs": counts.get(RUN_CANCELLED, 0),
        "running_runs": counts.get(RUN_RUNNING, 0),
        "pending_runs": counts.get(RUN_PENDING, 0),
        "success_rate": round(done / total, 4) if total else 0.0,
        "avg_faithfulness": round(float(avg_row[0]), 6) if avg_row[0] is not None else None,
        "scored_samples": int(avg_row[1] or 0),
        "total_tokens": int(tokens or 0),
        "total_cost_usd": round(float(cost or 0), 6),
    })
```

> 注册位置必须在 `GET /{run_id}` **之前**，否则 `stats` 会被当成 `run_id` 解析 → 422
> （实测过：旧版本 8200 就返回 `参数校验失败: path.run_id`）。已用 `app.routes` 顺序验证。

### 2. 停止接口（`POST /eval/runs/{id}/cancel`）

```python
@router.post("/{run_id}/cancel", summary="停止评测任务（running / pending → cancelled）")
def cancel_run(run_id: int, _: CurrentUser = Depends(require_admin), db: Session = Depends(get_db)):
    run = _get_run(db, run_id)
    if run.status not in (RUN_PENDING, RUN_RUNNING):
        raise HTTPException(status_code=409, detail=(
            f"任务 {run.run_no} 当前状态为 {run.status}，只有 pending / running 可以停止"
            "（已结束的任务请用删除）"))

    previous = run.status
    run.status = RUN_CANCELLED
    run.finished_at = now()
    run.error_msg = f"用户手动停止（已处理 {run.processed_items}/{run.total_items}）"[:1000]
    db.commit()
    ...
    data = run_to_dict(run, db.get(EvalDataset, run.dataset_id))
    data["previous_status"] = previous
    return ok(data)
```

**只写状态，不杀协程**。原因写进了 docstring：`execute_run` 由 FastAPI `BackgroundTasks` 调用，
跑在**响应所在的 ASGI 任务**里，从另一个请求 `task.cancel()` 会把连接处理一起打掉。

### 3. 执行器：把「取消」变成真能打断

改了三处：

**(a) 打分循环从 `as_completed` 改为显式 task 集合 + 带超时的 `asyncio.wait`**

```python
tasks: set[asyncio.Task] = {asyncio.create_task(_score_one(c, sem)) for c in score_ctxs}
while tasks:
    done, tasks = await asyncio.wait(
        tasks, timeout=settings.RUN_CANCEL_POLL_SECONDS,   # 2s：取消响应窗口
        return_when=asyncio.FIRST_COMPLETED,
    )
    for finished in done:
        ... 落库、计数、commit ...        # 先落库：已经花钱算出来的分不能扔
    if _current_status(db, run_id) == RUN_CANCELLED:
        await _cancel_tasks(tasks)         # 取消还在排队/打分的子任务，别继续烧额度
        _settle_cancelled(db, run, f"用户手动停止（已处理 {run.processed_items}/{run.total_items}，"
                                   "剩余样本不再打分，已产出得分予以保留）")
        return
```

旧实现用 `asyncio.as_completed(...)`，`return` 之后**剩余协程没人取消**——用户点了停止，
裁判仍在后台继续跑完那几条，钱照烧。现在显式持有 task 集合，取消即回收。

**(b) 取数阶段也能被打断**

```python
async def _wait_or_cancelled(db, run_id, task):
    while True:
        done, _ = await asyncio.wait({task}, timeout=settings.RUN_CANCEL_POLL_SECONDS)
        if done:
            return task.result(), False
        if _current_status(db, run_id) == RUN_CANCELLED:
            task.cancel()
            await asyncio.gather(task, return_exceptions=True)
            return None, True
```

**(c) `_current_status` 改为独立会话（这是最容易踩的坑）**

```python
def _current_status(db, run_id: int) -> str:
    probe = SessionLocal()          # 新会话 = 新事务 = 新快照
    try:
        return probe.execute(select(EvalRun.status).where(EvalRun.id == run_id)).scalar_one()
    finally:
        probe.close()
```

原因：MySQL 默认 **REPEATABLE READ**。轮询循环里连续调用本函数时中间没有 `commit`，
复用同一个 `db` 会一直用第一次读的快照 —— 表现为「点了停止毫无反应」。
这个坑只有在真的加了轮询之后才会暴露，单次检查发现不了。

**(d) 取消落定刻意不写 `metrics`**

```python
def _settle_cancelled(db, run, note=None):
    run.status = RUN_CANCELLED
    run.finished_at = now()
    run.error_msg = (note or "用户手动停止")[:1000]
    db.commit()
```

半轮样本的均值不能冒充整轮结论（与「零成功必须 NULL」同一口径）；
但**已产出的单样本得分全部保留**在 `eval_scores` 里 —— 那是真实花过钱的数据。

## 五、口径与取舍（为什么这么做）

1. **大盘为什么走后端聚合，而不是前端汇总列表？**
   列表是**分页**的（`size≤100`）。前端只能拿到当前页 20 条，「任务总数」「成功率」必然是错的 —— 这类"看着有数其实错的"指标比没有更危险。

2. **成功率 = done / total，cancelled 与 failed 都算未成功。**
   管理层的语义是「跑成了的比例」。想让取消不计入分母，就得再定义一套口径，反而解释不清。
   卡片副文案把 `完成/失败/取消` 三个数摊开写，避免读者自行脑补。

3. **平均 Faithfulness 用样本级加权，而不是 run 级均值的平均。**
   后者会让「2 条样本的任务」和「30 条样本的任务」同权 —— 一条小任务的极端分数能把大盘拉偏。

4. **取消只写标记位，不跨请求 cancel 协程。**
   见上文 docstring：`BackgroundTasks` 里的 `execute_run` 跑在 ASGI 任务内。用标记位 + 2s 轮询，实测
   - 取数阶段（0%）→ 2s 内生效；
   - 打分阶段（14%、29%）→ 当前批次落库后立刻生效。
   代价是「最多 2s 延迟」，换来的是不破坏连接生命周期。

5. **取消后 `metrics` 留空，但得分行保留。**
   与 v1.17「零成功必须 NULL，不能写全 null dict」同源。半轮均值若写进 `metrics`，
   A/B 看板会把它当成一次有效对比 —— 那是更严重的口径污染。

## 七、环境告警（与本次改动无关，但会影响演示）

截图期间发现：**当前裁判模型是 `kimi-k3`**（不是 `.env` 里的 `deepseek-v4.1-flash`，说明有人在系统设置页改过）。

- `POST /system/judge-config/preflight` → `{"ok": true, "model": "kimi-k3", "latency_ms": 1256}` —— 普通对话正常；
- 但真实评测**四项指标全空**：每条样本 `指标全空：裁判未返回可解析结果（疑似解析失败或输出被截断）`，
  整轮判 `failed`（见 run 103、101 的明细）。
- 表现与 v1.17 记录的「聊天正常、只有 RAGAS 全空」完全一致 —— 该模型不满足 RAGAS 的结构化输出解析。

**建议**：演示前在「系统设置 → 裁判模型配置」切回 `deepseek-v4.1-flash`（短名，无日期后缀）并点「保存并探活」，
再用一次 7 样本评测确认四项指标非空。本次两个功能（大盘/停止）不依赖裁判能否打分，已验证可用。
