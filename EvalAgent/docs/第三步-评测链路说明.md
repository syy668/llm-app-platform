# 第三步：核心评测逻辑（算力隔离）

## 一、链路

```
POST /api/v1/eval/runs            # 立即返回 run_id（PENDING），后台任务执行
   └─ runner.execute_run(run_id)
        1. judge.preflight()                 裁判探活：配置错立即失败，不浪费上游调用
        2. rag_client.query()   × N          httpx 并发调项目一 POST /api/v1/kbs/{id}/query
        3. judge.score()        × N          RAGAS 四项指标，to_thread 并发 + 外层硬超时
        4. 逐条写 eval_scores                 processed_items 实时 +1，前端进度条可动
        5. aggregate → eval_runs.metrics      零成功则 status=failed 且 metrics=NULL
```

**算力隔离**：项目一只负责答题（被测系统），裁判与落库全在项目二进程内。换被测系统不动打分口径，换裁判不动取数逻辑。

| POST | `/eval/runs` | 触发评测，立即返回 PENDING |

`/api/v1/eval/*` 与 `/eval/*` 双挂载。

## 三、实测结果（2026-10-26，真实项目一 8010 + 真实裁判）

7 条样本 / 4 分层，run A（top_k=3）耗时 42.5s、166357 tokens：

```
faithfulness=0.739  answer_relevancy=0.629  context_precision=0.800  context_recall=0.750
```

分层聚合（n=6 有效样本）暴露出指标的分层差异：

| 分层 | n | F | AR | CP | CR |
| --- | --- | --- | --- | --- | --- |
| easy | 2 | 0.550 | 0.000 | 1.000 | 1.000 |
| medium | 2 | 1.000 | 0.992 | 0.750 | 1.000 |
| hard | 1 | 1.000 | 0.856 | 1.000 | 1.000 |
| out_of_scope | 1 | 0.333 | 0.936 | 0.500 | 0.000 |

越界问题（"公司年假有多少天"）CR=0.000、F=0.333 —— 说明"资料里没有"被正确判为低分，这正是分层难例的价值。

## 四、踩到并修掉的三个坑

1. **思考型模型 content 为空**
   `deepseek-v4.1-flash-1017` 默认开思考，`max_tokens=20` 时全被 `reasoning_content` 吃光、
   `content=""`。RAGAS 解析空串 → 静默 NaN。已在 `ChatOpenAI(extra_body={"enable_thinking": False})`
   显式关闭，并把 `max_tokens` 提到 4096。

2. **RAGAS 重试退避把 run 拖死**
   默认 `RunConfig(timeout=180, max_retries=10, max_wait=60)`，一条样本解析失败后指数退避重试十次，
   **期间无日志无网络**，表现为进度卡在 6/7 数分钟不动。已收紧为 (90s, 3 次, 10s)，
   并在外层加 `asyncio.wait_for(300s)` —— 单条卡死只判该条失败，不阻塞整个 run。

3. **"ok 但四项全空"是假成功**
   首轮出现过 `status=ok` 但四项指标全 NULL 的行：RAGAS 把异常吞成 NaN。
   现在四空即判 `failed` 并写 `error_msg`，聚合只统计 `status=ok` 且非 NULL 的值。

## 五、A/B 的统计噪声（必须知道的局限）

同一份数据连跑两次，`top_k` 3→5 的 Δ 在两次实验里方向不一致（首轮 F +0.107，末轮 F −0.030），
而 `context_precision` 稳定 +0.2（拿到更多上下文 → 精确率口径受益）。
结论：**单次 A/B 的 ±0.05 级差异在裁判方差内，不可直接下结论**。
要做严谨对比，需要「同配置重复 N 次取均值」或「扩大样本量」，这一层（重跑聚合）是第四步之后的事。
