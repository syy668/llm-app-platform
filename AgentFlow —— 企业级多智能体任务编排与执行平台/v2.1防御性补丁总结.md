# AgentFlow v2.1 防御性补丁总结

> 定位：在 v2.0 七项生产级加固（564 项测试全绿）之上，针对大模型应用的三大经典风险——
> **幻觉、上下文污染、上下文超载**——补上的三个低侵入防御层。核心链路零重构，
> 新增 13 项专项测试，全量回归 577 项全部通过。

---

## 一句话概述

给"AI 会犯错"这件事上了三道保险：**输入端防撑爆、反馈端防带偏、输出端防编造**。

## 三项补丁

### 1. 上下文超载硬熔断（防 Token 爆炸与 OOM）

- **隐患**：多轮对话中 messages 无限增长，可能撑爆大模型上下文窗口或推高账单。
- **方案**：新增 `truncate_context` 纯函数，作为所有节点调用大模型的**统一入口拦截**——
  超过 12,000 字符时，强制保留 System 约束规则，从最早的历史消息开始丢弃；
  触发时输出 WARNING 日志（丢弃条数 + 原始长度），可审计。
- **收益**：上下文长度有硬上限，单次调用成本封顶；超限行为有日志留痕，不再是"静默黑洞"。

### 2. 工具错误脱敏（防底层报错"搞晕"模型）

- **隐患**：SQL 报错、连接超时等底层异常带着堆栈和乱码直接喂给大模型，模型被带偏后
  越修越错。
- **方案**：新增 `sanitize_tool_error`——按错误码/异常类型映射为简短的业务提示
  （如"之前的 SQL 语法有误，请检查表名或字段名"），硬上限 200 字符，**绝不携带堆栈**；
  原始细节仍保留在 Trace 中供人类排查。
- **收益**：模型收到的错误反馈"短、准、可执行"，SQL 自反思改写成功率提升；同时避免
  内部实现细节（表结构、连接串）泄漏进模型上下文。

### 3. 生成层强制溯源（防幻觉）

- **隐患**：大模型基于先验知识"编造"看似合理的结论，报告可信度不可控。
- **方案**：
  - Prompt 层：报告生成节点的 System Message 注入最高优先级强约束——每条结论必须按
    「结论：[xxx] 依据：[参考资料原句]」格式输出；资料不含答案时必须输出 `[NO_DATA]`，
    严禁编造；
  - 代码层：拦截 `[NO_DATA]` 输出，任务直接以 `NO_DATA_FOUND` 失败终止，
    **宁可带错误码的失败，不做静默的编造**。
- **收益**：每条结论可逐字溯源；"资料不足"从隐性风险变成显性、可告警的失败状态。

## 验证结果

- 新增 13 项专项测试（截断达标与 System 保序、脱敏不漏堆栈、[NO_DATA] 失败分支、
  并发日志归属等），**全量回归 577 项测试全部通过**。
- 顺手修复 2 个时间敏感的存量测试缺陷（仪表盘对账测试依赖"当日 UTC 窗口"，
  在本地 0~2 点运行会漂移失败），对账测试改为显式窗口，不再依赖运行时刻。

## 简历/述职一句话版本

> 为多智能体平台设计并落地三层大模型防御机制：上下文超载硬熔断（统一入口截断，
> 成本封顶）、工具错误脱敏回喂（200 字内业务提示替代原始堆栈，防模型被带偏）、
> 生成层强制溯源（Prompt 级「结论-依据」强约束 + [NO_DATA] 代码级拦截，防幻觉）；
> 全量 577 项自动化测试零失败，核心链路零重构。
