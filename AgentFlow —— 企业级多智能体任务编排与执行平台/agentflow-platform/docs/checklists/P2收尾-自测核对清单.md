## B. 任务 1：RAG 检索字段对齐（`app/memory/rag_schema.py`）

### B1 契约定义

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `chunk_id` | str | 1~128 字符 | 缺失时按 `doc_id#序号` 幂等派生 |
| `doc_id` | str | 1~128 字符 | 缺失时尝试从 `chunk_id` 前缀还原（Chroma 直出场景） |
| `score` | float | `[0,1]` | 经 `align_score` 统一收敛（见 B3） |
| `text` | str | 1~12000 字符 | 支持旧字段 `content` / `chunk_text` / `body` |
| `spans` | list[RagSpan] | `start ≤ end`，左闭右开 | 支持三种上游形态（见 B4） |
| `source` | str | ≤200 字符 | 缺省 `project1` / `mock-rag` |

- [x] `REQUIRED_CHUNK_FIELDS` 常量与任务书六字段**顺序一致**
- [x] `__all__` 导出 `RagChunk / RagQuery / RagResult / RagSpan / RagContractClient / check_kb_contract / validate_chunk / normalize_chunk / align_score / parse_spans / rank_chunks / build_rag_client / describe`
- [x] `RagChunk.to_kb_chunk()` → W2 `KbChunk`；`RagResult.to_kb_output()` → `KbSearchOutput`（旧链路可直接复用）

### B2 契约校验（字段缺失校验）

- [x] `validate_chunk(strict=True)`：**只判断不修补**，缺字段/空字段/类型不符一次性抛 `RagSchemaError`
- [x] `RagSchemaError.issues` 携带 `field_name / reason / index`，消息形如 `chunk[3].text: 字段缺失`
- [x] `normalize_chunk()`：**尽力修补**，别名映射 + `chunk_id` 派生 + `spans` 容错；正文/文档号补不出来才报错
- [x] `check_kb_contract(payload)`：一次体检，返回 `ok / chunks / issues / warnings / total / missing_fields`
- [x] `missing_fields` 口径 = 「上游是否给了」而非「是否补得上」——少字段即不达标（`ok=False`）
- [x] 兼容 5 种响应容器：`data.chunks` / `data.results` / `data.items` / `chunks` / `results` / 裸 list

### B3 相似度打分对齐

| 上游口径 | 输入 | 输出 |
|---|---|---|
| 归一化相似度 | `0.88` | `0.88` |
| 百分制 | `93`、`"87%"` | `0.93`、`0.87` |
| 余弦相似度 | `-0.2` | `0.4`（`(x+1)/2`） |
| 略微越界 | `1.5` | `1.0`（判为越界而非 1.5 分） |
| 非法值 | `None` / `"abc"` / `nan` / `inf` | `0.0` |

- [x] `align_score` 12 组参数化用例（含字符串百分号、负余弦、越界、NaN/Inf）
- [x] `rank_chunks` 按对齐后分数降序，并按 `chunk_id` 去重保留最高分（防重复占位）
- [x] `RagChunk` 构造期自动 `align_score`，模型层与函数层口径唯一

### B4 `spans` 三形态解析

- [x] `[[2, 4]]`（数对）

### B5 `MOCK_EXTERNAL_RAG` 兜底开关

## C. 任务 2：长期记忆去重 + 时间衰减 + TTL（`app/memory/memory_lifecycle.py`）

### C1 语义去重

- [x] 相似度算法：`tokenize`（中文 2-gram + 英文词 + 数字，复用分层记忆既有切词）→ `crc32` 特征哈希到 128 维 → L2 归一化 → 余弦
- [x] `set_embedder(fn)` 可注入项目一真实 embedding，其余逻辑不变（含用例验证）
- [x] `find_duplicate()`：只看**同 user** 最近 `MEMORY_DEDUP_CANDIDATES=50` 条，跨用户绝不合并
- [x] 命中阈值 `MEMORY_DEDUP_THRESHOLD=0.88`（可调）；`≥0.9999` 提前短路
- [x] 合并策略：正文取**更长**、`importance` 取**更高**、`hit_count +1`、`expires_at` 刷新
- [x] 合并后若正文变化且已有 `chroma_doc_id` → 回写向量库（best-effort，失败只记警告）
- [x] 并发删除目标条目 → 返回 `None` 并退回「新增」路径，不丢数据
- [x] 阈值调高到 0.999 时近似文本不再合并（用例覆盖配置语义）

### C2 时间衰减

- [x] `decay_weight(Δt) = max(min_weight, exp(-λ·Δt))`，Δt 以**天**计
- [x] λ=0.01 → 半衰期 69.31 天（用例断言 `exp(-λ·half_life)=0.5`）
- [x] `MEMORY_DECAY_MIN_WEIGHT=0.05` 下限，保证久远高价值结论不被压到 0
- [x] `λ=0` 时不衰减；负数/未来时间按 0 处理
- [x] `effective_score = raw × w × (1 + 0.06×(importance−3))`，结果裁到 `[0,1]`
- [x] 召回重排：同文同龄 → 同分；同文不同龄 → **新者优先**，分数比 ≈ `exp(-λ·Δage)`（用例断言 rel=2%）
- [x] `MEMORY_DECAY_REFILTER=false` 默认只降权不过滤；置 true 时按 `min_score` 二次过滤（用例覆盖两种）

### C3 TTL 自动清理

- [x] 归档即写 TTL：`MEMORY_LONG_TTL_DAYS=180`（`0` = 永久，保持原语义）
- [x] 合并时刷新 TTL（避免「老条目因为被复用而永不过期」）
- [x] 召回期过滤：`expires_at ≤ now` 的条目**不进注入**（衰减关掉也照样过滤）
- [x] `purge_expired()` 返回 int（与原接口一致），实际清理 mid + long 两层
- [x] `purge_expired_details()` 返回 `{"mid": n, "long": n}` 明细（运维观测用）
- [x] `MEMORY_TTL_CLEANUP_ENABLED=false` → 退回原实现（只清 mid）

### C4 对外接口不变

- [x] `LifecycleMemoryService` 是 `LayeredMemoryService` 的**子类**；公开 API 为父类超集
- [x] 四个被覆盖方法的 `inspect.signature` 参数名/顺序与父类**逐一相等**（用例断言）
- [x] `purge_expired` 返回类型仍为 `int`；`archive_long` 仍返回 `MemoryRecord | None`；`recall` 仍返回 `list[MemoryHit]`；`create_memory` 仍返回 `MemoryRecord` 并在关闭时抛 `MemoryDisabledError`
- [x] `build_lifecycle_memory()` 工厂：关闭时返回父类实例（行为完全一致）

## H. 已知边界与后续

1. **CI 覆盖率清单未追加**（见 G）：需在 `ci-test.yml` 的覆盖率步骤加两行 `--cov=`；
   追加后 `--cov-fail-under=85` 自动覆盖本轮两个模块（实测 93.71% / 88.70%）。
2. **语义去重是「字面级近义」而非「模型级语义」**：默认用特征哈希余弦（离线、零依赖、确定性）。
   真正跨表述的语义合并需注入项目一 embedding（`set_embedder(...)`），届时阈值建议上调至 0.95。
3. **TTL 只覆盖 mid / long 两层**：short 层本就是 Redis 24h TTL，由存储自身回收，不重复管理。
4. **`purge_expired` 无内置调度**：当前由调用方（管理 API / 定时任务）触发；若要自动清理，
   可在 W5-Part2 的容器里加一个轻量 cron 服务调用它（不改任何业务代码）。
5. **RAG 契约版本 `p2.1`**：字段语义不兼容变更时必须同步递增，并在 `describe()` 中体现。
6. **`spans` 不参与召回打分**：仅用于前端高亮/提示词定位，越界自动裁切，不影响分数。
