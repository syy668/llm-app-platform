## 1. RAGAS 评测超时静默丢失指标的根因解决

**现象**：批量评测跑完，部分样本四项 RAGAS 指标全为 NULL，且无任何报错日志，前端图表出现"空洞"。

**根因**：RAGAS `evaluate()` 库默认整体超时 180s；长样本（长 ground_truth + 多上下文）判分耗时超过该阈值后，RAGAS 内部把该样本指标**静默置 None**，不抛异常、不打日志，上游无从感知。叠加 Judge LLM 网络抖动偶发超时，指标缺失被放大。

**解决**（三层治理，`app/config.py` + `app/services/eval_service.py`）：
1. `EVAL_RAGAS_TIMEOUT` 整体超时上调至 600s（可覆盖）；
2. `EVAL_LLM_TIMEOUT=120s` + `EVAL_LM_MAX_RETRIES=3`：Judge LLM 单请求级超时与重试，与 Agent 链路容错策略对齐；
3. **空值口径统一**：指标为 NULL 的样本不参与均值（AVG 忽略 NULL）、不判入 BadCase、A/B 对齐记 Δ=null —— 保证"缺失"不污染统计口径，同时超时样本数随 run 详情返回，可观测。

**一句话**：把"静默丢失"改造成"超时可控 + 缺失可观测 + 口径不污染"，评测结果的空洞从未知故障变成可解释数据。

## 2. 空数据集 / 分层难例 / A/B 对比的空值口径统一方案

**现象**：同一份"指标缺失"在三个功能里出现三种解释：均值算不算？BadCase 算不算？A/B 差值算不算？早期版本各自为政，前端图表口径互相矛盾。

**方案**：全站统一"NULL 不参与，但必须可见"的口径，并在 SQL 层而非前端实现：
- **分层指标**（`GET /eval/runs/{id}/stratum_metrics`）：`eval_run_scores LEFT JOIN eval_dataset_items` 按 stratum 分组，`AVG` 忽略 NULL；stratum=null 统一表示"未分层"（含历史数据与样本已删除），单列返回不丢弃；
- **BadCase 筛选**（`GET /eval/runs/{id}/badcases`）：筛选条件 `metric IS NOT NULL AND metric < threshold` 在 SQL 层完成，前端零计算；
- **A/B 对比**（`POST /eval/runs/compare`）：样本按 question（strip 归一）对齐，单侧缺失样本 `diffs=null` 不参与汇总；汇总均值优先取 run.metrics（与评测落库同口径），未落库时由得分现算兜底，`diff_threshold=0.1` 随响应返回。

**一句话**：把空值语义收敛成一条全站规则（SQL AVG 忽略 NULL + NULL 可见不丢弃），三处功能一次讲清，杜绝口径漂移。

## 3. sqlite 内存库多线程主键不自增的测试兼容方案

**现象**：pytest 走 TestClient（子线程发请求）+ sqlite 时，插入报 `NOT NULL constraint failed: eval_runs.id`；显式传 id 又出现并发下互踩。生产 MySQL 无此问题。

**根因**：模型的 BigInteger 主键在 MySQL 下是 `BIGINT AUTO_INCREMENT`，但 sqlite 把 `BIGINT PRIMARY KEY` 渲染为普通整数列——只有 `INTEGER PRIMARY KEY` 才能借用 rowid 别名机制自增。另外 `sqlite:///:memory:` 默认连接池下**每线程各持一个独立内存库**，建表与查询不在同一个库。

**解决**（全部固化在 `tests/conftest.py`，业务代码零改动）：
1. **方言级 monkeypatch**：`@compiles(BigInteger, "sqlite")` 把 BIGINT 渲染为 INTEGER，恢复 rowid 自增；
2. **文件型 sqlite + StaticPool + check_same_thread=False**：全局单连接跨线程共享，同时落盘 tmp 目录便于失败排查（替代内存库的"各连各的"）；
3. 封装 `sqlite_engine` / `eval_db` 共享夹具，150+ 用例自动复用，新增测试无需再感知兼容细节；该补丁仅作用于测试进程的 sqlite 方言，生产 MySQL 不受任何影响。

**一句话**：用 SQLAlchemy 方言编译钩子 + StaticPool，把"测试环境方言差异"从业务代码中剥离，测试与生产彻底解耦。

## 4. 双 Token 一次性轮换 + Redis 黑名单实现会话踢下线

**现象**：旧方案单 access token 7 天长效，改密码/封号后旧 token 依然有效，无法主动踢下线；token 一旦泄露风险窗口极长。

**方案**（`app/core/security.py` + `app/services/auth_service.py`）：
1. **双 Token**：access_token 缩短为 30 分钟（Redis session，HMAC-SHA256 签名防伪造，滑动过期）；refresh_token 7 天；
2. **一次性轮换**：`POST /auth/refresh-token` 校验（签名 + 黑名单 + Redis 存在性三重）通过后**立即删除旧 refresh_token 并签发新对**，旧令牌即使被截获也只有一次机会且即刻失效；旧端点 `/auth/refresh` 保留向后兼容；
3. **Redis 黑名单**：登出时把 refresh_token 写入黑名单（TTL 与剩余有效期一致），`get_refresh_user_id` 校验时黑名单优先拦截——即使令牌未过期也无法再刷新，实现改密/封号/登出的即时踢下线；
4. 存储开销可控：黑名单 key 仅在被拉黑后的剩余有效期内存在，自动过期回收。

**一句话**：短期 access + 一次性轮换 refresh + 黑名单三件套，把"token 泄露"的风险窗口从 7 天压缩到一次请求。

## 5. Axios 并发 401 请求的锁 + 请求队列实现无感刷新

**现象**：页面首屏并发发出 N 个请求，access_token 过期时 N 个请求同时收到 401，若各自触发刷新：① refresh_token 一次性轮换导致后 N-1 次刷新拿着已被删除的旧 token 全部失败 → 用户被误踢下线；② 刷新风暴打爆后端。

**方案**（`evalagent_vue/src/api/http.ts` 响应拦截器）：
1. **isRefreshing 锁**：第一个 401 触发刷新并上锁，其余 401 直接进队列等待；
2. **请求队列**：等待中的请求把 resolve/reject 存入队列，刷新成功后用**新 token 批量重发**、原样归还响应给业务代码，业务层完全无感；
3. **刷新失败兜底**：清空本地凭据（含黑名单化旧 refresh_token）→ 跳转登录页，队列内请求统一 reject；
4. 与后端约定 401 语义：仅 access 失效走无感刷新，refresh 也失效（黑名单/过期）才落地为跳转。

**一句话**：锁 + 队列把 N 次 401 收敛成 1 次刷新 + N 次重放，与后端一次性轮换语义严丝合缝。

## 6. 前后端分离 RBAC 双重权限校验方案

**现象**：前端藏了管理员入口但接口裸奔（Postman 直调即越权）；或后端全量校验但前端路由不拦截，普通用户满屏 403 体验差。

**方案**（`app/api/deps.py` + Vue 路由守卫）：
1. **后端三级依赖注入**（唯一信任源）：
   - `get_current_user`：Bearer token → Redis session 解析（签名/过期/黑名单），并把 user_id 挂到 request.state 供错误日志追踪；
   - `get_current_admin`：叠加角色校验，非 admin 抛 403（统一异常处理器返回 `{code:403}`）；
   - 资源级校验：知识库三级（admin / owner / kb_permissions 授权 read|write）、会话仅本人（管理员也不例外）；
2. **前端路由守卫**：按角色控制页面与入口可见性——**仅作体验优化**，注释明确"一切以服务端为准"；401/403 统一由 Axios 拦截器分流（401 走无感刷新，403 全局提示）；
3. **审计闭环**：管理员敏感操作写 `operation_logs`（操作人/动作/对象/IP）；错误日志带 user_id + trace_id，越权尝试可追溯。

**一句话**：前端管"看得见"，后端管"进得来"——依赖注入实现的三级校验让权限规则可组合、可测试，150+ 用例覆盖 401/403 全分支。

## 附：工程化收尾补充亮点

- **Trace 全链路**：全局 TraceID 中间件（复用 `X-Request-ID`）→ ContextVar → 日志 Filter，所有日志自动携带 trace_id；响应头回写 `X-Trace-ID`；LangChain 回调采集节点耗时/token 用量落库 trace_logs / trace_tool_calls；
- **异常分级**：`APP_ENV=dev` 返回完整堆栈、prod 只返回简洁提示；所有异常 error 级日志含 trace_id/路径/用户ID；
- **Docker 单机一键部署**：后端多阶段镜像（builder venv → runtime 瘦身）+ 前端 node→nginx 两阶段 + 4 服务 compose 编排（MySQL/Redis 健康检查驱动启动顺序），`deploy/start.bat|.sh` 一条命令拉起，宿主机零语言环境依赖；
- **测试固化**：sqlite 兼容方案入 conftest，OpenAPI 一键导出（`scripts/export_openapi.py`）保证接口文档与代码同源。
