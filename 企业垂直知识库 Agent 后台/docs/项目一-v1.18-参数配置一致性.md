# v1.18 对话参数与系统配置的「是否真的生效」核查与修复

日期：2026-10-24
起因：「智能对话 → 参数配置」的工具开关开了没开一样吗？「系统配置」的 12 项是生效还是只展示？

## 一、结论

两处都是**真实生效**的——没有一个控件是纯展示。但对话页有三处「生效了却看不出来」的缺陷，
会让用户得出「开关没用」的结论，已在本次修掉。

### 1.1 对话页「参数配置」（4 类控件）

| 控件 | 是否生效 | 生效路径 | 实测证据 |

## 二、发现并修复的三个缺陷

### 缺陷 1：关闭开关后，对外仍显示「知识库检索」

`route_condition` 只改变走哪条边，**不会改写 `state["route"]`**。于是：

```
分类判 rag → 参数关了 rag → 条件边执行 direct → 但 state["route"] 仍是 "rag"
                                     ↓
前端徽标显示「🏷️ 知识库检索」、落库 agent_route=rag、Trace 大盘统计成 rag
```

用户看到「关了开关 → 徽标还是知识库检索 → 回答还是检索相关」，自然判断成开关无效。

**修法**：抽出 `disabled_route(state)` 纯函数（`app/agent/graph.py`），让
`route_condition` 与对外返回共用同一判定；`run_agent` 返回改为：

- `route` = **实际执行**的路由（被关闭则为 `direct`）
- `route_requested` = 分类原本想走的路由
- `route_disabled` = 被参数关掉的那一路（`None` = 未关闭）

流式链路同步：`route` 事件直接下发 effective route + `disabled`；`done` 事件、
`agent_route` 落库、`handler.route` 全部改用 effective route。

前端 `RouteTag.vue` 增加描边徽标「已关闭知识库检索」，配 tooltip 说明
「右栏参数配置里关闭了「知识库检索」，本轮按直接回答处理（未检索/未查询）」。

### 缺陷 2：关了检索，答案变成「知识库中未找到相关信息」

`_ANSWER_SYSTEM_PROMPT` 原本是无条件的两句：

> 仅依据提供的资料/数据回答……如果资料中没有能回答问题的信息，**必须明确说明「知识库中未找到相关信息」**

direct 分支手上没有任何资料，模型照着系统提示就把「未找到」当答案返回。

**实测（修复前）**：

```
关 rag → route=rag（错）sources=0 context=0
       → answer = "知识库中未找到相关信息"
```

用户视角：**关了开关反而更差**，本来能靠模型自身知识回答的问题，现在直接说找不到。

**修法**：把资料约束改成条件式——

> 仅在提供了资料/数据时，才要求只依据资料回答并注明来源；**未提供任何资料的轮次，
> 请直接用你自己的知识正常回答**，不要声称检索过、也不要输出「知识库中未找到相关信息」
> 这类本轮无据可依的话。

RAG 分支原有的「若结果中没有足够信息，请明确说明知识库中未找到」保留在
`tool_output` 注入里，**按需生效**，不再全局污染。

**实测（修复后）**：

```
关 rag → route=direct  requested=rag  disabled=rag  sources=0
       → answer 用通用知识给出区间（400-600/600-900），并说明"未提供具体制度文件"
```

### 缺陷 3：配置页改了模型，Trace 仍记旧模型

`app/core/tracing.py` 落库用的是 `settings.llm_model`（`.env` 快照），
而配置页写的是 `runtime_config` 覆盖值。真实库核对：

```
runtime_config.llm_model = 'qwen3.7-plus'   ← 实际在跑
settings.llm_model       = 'deepseek-chat'  ← .env 残留
trace_logs 分布：('deepseek-chat', 1538)    ← 1538 条全记错
```

后果不只是显示难看：按模型做成本归因、质量对比、A/B 结论**全部失真**。

**修法**：取值顺序与工厂对齐——`runtime_config 覆盖值 > .env > 兜底`。

## 五、已知边界（未改）

1. **`max_tokens` 不在配置页**：走 `.env` 的 `LLM_MAX_TOKENS`（v1.16），改了需要重启。
2. **Embedding 刻意无控件**：换 embedding 必须重跑全部文档向量化，做成一个下拉框等于给用户一个「一键把库搞坏」的按钮。分块/检索参数同理留在 `.env`。
3. **`runtime_config` 是进程内缓存**：单进程 uvicorn 没问题；将来上多 worker，A 进程保存的配置 B 进程不会感知，需要改为按 mtime 失效或走配置中心。
4. **`llm_provider` 切到 anthropic 需装 `langchain-anthropic`**：未装时保存会提示，不会静默失败。
